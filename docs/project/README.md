# docs/project 内 spec/plan 存放与归档机制

brainstorming / 写计划会话产出的**设计记录（spec）与实施计划（plan）**按所属模块就地存放，不设独立集中目录。维护方：AI（机制正本即本文档；`CLAUDE.md` 文档体系表有对应条目）。

## 存放位置

| 文档所属 | 存放目录 | 示例 |
|---|---|---|
| idea 阶段模块（尚无正式 design.md） | `docs/project/idea/<模块>/` | `idea/购物车/2026-09-11-降价提醒-design.md` |
| 已立项模块 | `docs/project/<模块>/` | `<模块>/2026-09-11-<主题>-design.md` |
| 跨模块 / 全局改动 | `docs/project/全局/`（或对应区域目录） | `全局/2026-09-11-<主题>-design.md` |

- 文件命名：`YYYY-MM-DD-<主题>-design.md`（spec）、`YYYY-MM-DD-<主题>-plan.md`（plan）；日期前缀保证唯一，**归档不改名**。
- spec 与 plan 同目录混放（plan 头部 `**Spec:**` 字段互指），不设子分目录。
- 模块目录**不预建**，随第一份对应文档产生。
- `idea/` 目录维护权属开发者——AI 产出的 spec/plan 存于其中时**只动自己产出的文件**。

## 文件夹说明文档

每个子文件夹下须有一个以该文件夹命名的说明文档，说明该文件夹的功能作用与使用方式：

- 现有：`../docs.md`（docs/ 体系导读）、`../log/log.md`（日志目录说明）、`project.md` 顶部「文件夹说明」节（本目录说明）
- AI 新建子文件夹（`idea/`、模块目录、`archive/` 等）时，**同步创建 `<文件夹名>.md` 说明文档**
- `project.md` 特殊：主体为开发者主导的项目总介绍，仅顶部文件夹说明节由 AI 维护

## 归档

落地或废弃后移入所属目录的 `archive/` 子目录（spec 与 plan 共用）：

| 判定 | 依据 | 动作 |
|---|---|---|
| 落地归档 | 状态行或日终日志明确记录「实施完成」。本项目落地判定：**代码改动通过模块自测入口 / `python shopping_agent.py demo` 回归即算落地，不等人工冒烟**；纯文档类改动以开发者验收确认为准 | 移入 archive/，状态行追加归档记录 |
| 废弃归档 | **开发者明确说**「废弃 / 被新设计取代」（AI 不自行判定废弃） | 移入 archive/，状态行标注「已废弃（原因）」 |
| 留守 | 待实现、会话进行中 | 不动 |
| 拿不准 | 依据不明 | 不动，报告开发者 |

配套规则：spec 落地归档时，其对应 plan（`**Spec:**` 字段指向该文档者）一并归档。模块升级路径：idea 阶段模块正式立项（design.md 迁入正式目录）时，其 spec/plan 一并迁入。

## 触发时机（全自动，无需开发者口令）

1. **写 / 追加日终日志时**——记录「实施完成」的那一刻就是归档时刻；
2. **写新 spec / plan 时**（清点其所属目录）。

开发者也可随时说「归档一下」触发即时清点（兜底）。

## 归档动作（固定四步）

1. `mv` 至所属目录的 `archive/`，文件名不变；
2. 文档顶部状态区追加一行：`- 已归档：YYMMDD 随 <功能> 落地`（废弃则 `- 已归档：YYMMDD 废弃（<原因>）`）；
3. 全库检索该文件旧路径，更新**活动文档**（模块 designs-specs、CLAUDE.md、本 README）中的路径引用；**历史日志（docs/log/）不改**，同批移动的关联引用顺手更新；
4. 当天日终日志记一笔。

## 回改通道

人工验收后若需回改已归档文档：直接在 archive/ 内改，或移回所属目录（状态行同步改回），日志记录。**归档只是位置变化，文件永不删除。**
