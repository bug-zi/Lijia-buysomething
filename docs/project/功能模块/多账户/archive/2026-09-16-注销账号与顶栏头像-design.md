# 注销账号 + 顶栏用户名头像 设计文档（spec）

- 日期：2026-09-16
- 状态：待开发者审阅
- 来源需求：`docs/project/新功能开发区.md` 待完成区两项：
  1. 补充「注销当前账号」的功能；
  2. 右上角显示用户名+头像，用户名在左，头像在右；头像优先使用用户上传的，没有就用系统默认的，不要用当前的这个图标。
- 已确认决策：「注销」= **删除账号**（永久删除账户与全部数据，非退出登录）；删除前**输入登录密码确认**；顶栏头像兜底用**用户名首字母+主题色色块**（性别未填时无系统默认头像图）；实现采用「方案A：后端真删 + 前端菜单入口」。
- 与上一轮关系：上一轮 spec（2026-09-15-多账户机制）曾把「删除账户」列为非目标，本轮将其转正落地；「退出登录」保持不变，二者并存语义不同。

## 1. 背景与目标

现状：
- 多账户机制已落地（注册/登录/退出/token 鉴权，数据按 `accounts/<用户名>/` 隔离），但没有删除账户的能力——不要的账户会永久残留在 `accounts.json` 与数据目录里。
- 顶栏账户胶囊（`acct-chip`）目前是 Material Symbols `person` 图标在左 + 用户名在右；用户中心其实已支持上传自定义头像与性别系统默认头像（男/女两张），但顶栏没有用上。

目标：
- 新增「注销账号」：验证登录密码后，永久删除该账户条目与 `accounts/<用户名>/` 全部数据，退回登录门。
- 顶栏改为 **用户名在左、头像在右**；头像取值：用户上传的自定义头像 → 性别系统默认头像 → 首字母色块兜底，不再使用 `person` 图标。

非目标（YAGNI）：删除后恢复/回收站、软删除、管理员视角的账户列表管理、修改密码、密码找回。

## 2. 方案选型

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. 后端真删 + 前端菜单入口 | 验密码 → accounts.json 原子移除条目 → `shutil.rmtree` 账户数据目录；前端菜单入口 + 密码确认弹窗 | **采用**：语义彻底，符合「注销」直觉 |
| B. 软删除（目录改名 `<用户名>.deleted`） | 数据保留可反悔 | 弃：数据仍占空间，「注销」语义不干净，本地单机无此需求 |
| C. 仅前端退出+提示手动删目录 | 不动后端 | 弃：不满足需求本体 |

## 3. 后端设计

### 3.1 `core/account_manager.py` — `AccountStore.delete_account(username, password)`

- 流程：.strip() 用户名 → 在现有模块级 `_lock`（RLock）内读表 → 找不到账户返回 `{"ok": False, "error": "账户不存在。"}` → `_hash_password(password, salt)` 与存储的 `password_hash` 比对，不一致返回 `{"ok": False, "error": "密码不正确。"}` → 通过则：
  1. `data["accounts"].pop(username)` 后 `_write(data)`（沿用临时文件 + `os.replace` 原子写）；
  2. 删除数据目录 `DATA_ROOT/<用户名>/`：仅当目录 realpath 位于 `DATA_ROOT` realpath 之下才 `shutil.rmtree`（防路径意外）；目录不存在则跳过，不报错。
  3. 成功返回 `{"ok": True}`。
- 该账户残留 token 自然失效（条目已不存在，`resolve()` 返回 None）。
- 顶部 import 补 `shutil`。
- 自测：扩展模块底部 `__main__` 自测块，覆盖：密码错误不删；密码正确后 accounts.json 条目消失、账户目录及其内文件消失；删除后再 `resolve(旧token)` 为 None。

### 3.2 `web_server.py` — 新端点 `POST /api/auth/delete_account`

- 路由位置：do_POST 中放在 `user = self._authenticate()` 鉴权**之后**（与业务端点同级，区别于 register/login/logout 的免鉴权区），即必须持有效 token 才能调用。
- 入参 `{"password": "..."}`；调用 `account_manager.ACCOUNTS.delete_account(user["username"], password)`；成功 `{"ok": True}`，失败 400 + 具体错误文案。

## 4. 前端设计（index.html）

### 4.1 顶栏账户胶囊改造

- `acct-chip` 结构由「图标+用户名」改为「**用户名 + 头像**」（顺序对调）：`<span id="acct-name">` 在左，右侧 24px 圆形头像。
- 头像取值新增 `topbarAvatarHtml()`：
  1. `_uc.avatar`（用户上传，data URI/本机 resource 路径）→ `<img>`；
  2. 性别默认图 `/resource/avatar_male.png` / `avatar_female.png` → `<img>`；
  3. 兜底：用户名首字母 + 主题色色块（复用用户中心现有 `uc-avatar` 的 class 体系与 `avatar_color` 偏好，不用 person 图标）。
- 刷新时机（同一函数 `refreshAcctChip()`，登录/更新头像后各调一次）：登录成功进入主界面（applyAuthed）、用户中心保存账户信息、头像上传成功、恢复默认头像、引导向导保存完成。
- 无 emoji；警示/普通配色均随主题色系与深浅模式。

### 4.2 注销账号入口与确认弹窗

- 账户菜单（`acct-menu`）「退出登录」下方新增「注销账号」按钮：Material Symbols `delete_forever` 图标，警示色用主题色系暗红（非彩亮饱和色）。
- 点击弹确认弹窗（复用现有弹窗/确认体系扩展一个带输入框的形态）：文案含红字警示「账号及全部数据将被永久删除，不可恢复」，含密码输入框 + 取消/确认两键。
- 确认 → `POST /api/auth/delete_account`：
  - 成功：清 token 与本账户 localStorage 缓存（复用 doLogout 的清理路径）→ 回登录门 → toast「账号已注销」。
  - 密码错误：弹窗内就地提示，不关闭弹窗，可重输。
- 账户菜单内「退出登录」与「注销账号」并排共存，文案明确区分。

## 5. 边界与错误处理

- token 失效/未登录时调删除端点 → 401 统一拦截，前端清 token 回门。
- 密码连错仅就地提示，不做锁定（本地单机、无爆破面）。
- 数据目录缺失/已被手动删除 → 只删条目，成功返回，不报错。
- 删除动作期间其他请求（同账户并发）由现有 `_lock` 与 401 机制自然兜底；不引入额外锁。
- 删除成功后服务端不清理全局登录态（平台抓取登录态本就全局共享，与账户无关）。

## 6. 测试计划

- 脚本级（account_manager `__main__` 自测块）：密码错误不删；密码正确条目+目录均消失；旧 token 失效；目录缺失时仅删条目不报错。
- 浏览器实测（测试卫生：不进真实搜索链路）：新建测试账户 → 顶栏显示用户名+头像（分别验证：上传自定义头像 / 选性别默认 / 未填性别首字母色块三种形态）→ 用户中心换头像后顶栏即时刷新 → 注销账号输错密码就地报错 → 输对密码删除后回登录门 → 用旧 token 请求返回 401 → 重新注册同名账户为全新空数据。
