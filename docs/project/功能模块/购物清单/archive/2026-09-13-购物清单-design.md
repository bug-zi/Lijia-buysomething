> 创建于 2026-09-13（brainstorming 与开发者逐项对齐后定稿）

> 来源：docs/project/新功能开发区.md 待完成区条目「购物清单」

## 1. 背景与定位

用户突然产生一个购物需求（可能是具体商品，也可能是模糊痛点如「夏天房间太热想凉快点」），但当下不想或不知道怎么开聊。购物清单提供存放处：先把需求记下，之后任一时刻可一键转成购物对话。

**与虚拟购物车的边界（不重复）**：

| | 购物清单（本功能） | 虚拟购物车（现有 virtual_cart.py） |
|---|---|---|
| 阶段 | 推荐**之前**的需求池 | 推荐**之后**的商品收藏 |
| 条目内容 | 一句话需求，无商品、无价格、无链接 | 具体商品（名称/平台/URL/价格） |
| 核心动作 | 转成对话发起推荐 | 价格监控、备注、移除 |

全链路：**清单（需求）→ 对话购物（解析→搜索→推荐）→ 购物车（收藏商品）→ 订单模拟**。

## 2. 决策记录（开发者已确认）

1. **定位**：购买前需求池，独立功能模块（否决「购物车扩展无商品条目」方案——购物车语义不被污染）。
2. **添加入口**：双入口——清单页手动添加 + 对话指令「记到清单：xxx」。
3. **转对话交互**：点「去推荐」→ 切到对话页、原文填入输入框并聚焦，**填入不发送**；用户可补充预算等再手动发送（避免误触真实抓取，符合抓取克制红线）。
4. **生命周期**：两态（待处理 / 已完成）；已完成折叠在列表底部，可一键清空；转对话后不自动改状态，由用户手动标记。

## 3. 方案选择

代码落位采用**独立模块**：`core/shopping_list.py` + 根目录 `shopping_list.json`，与 `virtual_cart.py` 同构。否决方案：塞进 virtual_cart.py 作第二种条目类型（语义混杂）、塞进 user_center.py（语义错位）。

## 4. 数据模型与存储

```python
@dataclass
class ListItem:
    id: str          # uuid 前 8 位
    content: str     # 需求原文（自由文本）
    created_at: str  # "YYYY-MM-DD HH:MM:SS"
    done: bool = False
```

- 模块：`core/shopping_list.py`，类 `ShoppingList`，接口对齐 VirtualCart 风格：
  `add(content)` / `remove(index)` / `toggle_done(index)` / `clear_done()` / `clear()` / `list_text()` / `to_list()`。
- `add` 去重：与现有待处理条目 content 完全相同则提示已存在，不重复添加。
- `list_text()`：Markdown 表格（#/内容/状态/记录时间），空态提示引导两种添加入口。
- **编号基准**：列表按存储顺序（添加先后）统一编号，含全部条目（待处理在前、已完成在后仅是前端折叠显示，不改编号）；对话指令「第N项」即此编号。
- 持久化：根目录 `shopping_list.json`，UTF-8，`ensure_ascii=False`。
- 不加备注字段：content 本身即自由文本（YAGNI）。

## 5. 后端 API

仿 `/api/cart` 风格，在 `web_server.py` 增加：

- `GET /api/shopping_list` → `{ok, items, pending_count}`
- `POST /api/shopping_list`，body `{action, ...}`：
  - `add` `{content}` — 空内容返回错误提示
  - `remove` `{index}`
  - `toggle_done` `{index}`
  - `clear_done`
  - `clear`

## 6. 对话指令（双入口之一）

在对话指令层（与购物车指令同层，命中后不进需求解析链路）：

| 指令 | 行为 |
|---|---|
| `记到清单：xxx` | 添加条目，回复确认 |
| `我的清单` / `展示我的清单` | 返回 `list_text()` |
| `从清单移除第N项` | 移除 |
| `完成第N项` | 标记完成 |

指令识别用前缀/正则匹配，纯规则实现。

## 7. 前端 UI（单文件 index.html）

- 侧边栏新增 Tab「购物清单」，位置在「虚拟购物车」**之前**（对应链路顺序）。图标 Material Symbols `checklist`，徽标显示待处理数（沿用 cart-badge 模式）。
- 页面结构：顶部添加输入框 + 添加按钮；待处理列表；已完成折叠区（默认收起，可展开）；「清空已完成」按钮。
- 条目操作按钮：「去推荐」「完成/取消完成」「移除」。
- 使用走查：侧边栏点「购物清单」→ 输入「夏天房间太热想凉快点」回车 → 进待处理列表 → 数日后点该条「去推荐」→ 自动切对话页、原文填入输入框并聚焦 → 用户补预算后回车 → 走既有推荐链路 → 满意后「把第1款加入购物车」→ 回清单标记完成。
- 「去推荐」实现：`sendMsg` 所在输入框赋值 + `switchTab` 到对话页 + 聚焦，**不自动发送**。

## 8. 红线合规

- 「去推荐」填入不发送，不自动触发抓取（抓取克制）。
- 全程无 emoji；图标一律 Material Symbols；配色用主题色系 CSS 变量，深浅色模式与四套皮肤下表现一致。
- 第一期零 LLM 调用，纯规则 CRUD，天然满足 AI 全链路兜底。
- 数据本地 JSON 存储，无网络依赖，不涉 Key。
