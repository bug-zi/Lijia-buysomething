# 模块规划与去留 · design

> 创建于 2026-09-13（问题疑惑区第3轮讨论结论，经开发者逐项确认）

## 背景

开发者从同伴接手项目，对订单&物流、Top3推荐等模块功能不熟。本轮先由 AI 讲解各模块现状，再逐项商讨去留，最终敲定模块划分并在 `docs/project/` 建立各模块子文件夹。

## 项目定位（本轮敲定）

**个人自用为主，兼顾演示。** 取舍标准：自用价值优先，演示性模块看情况精简。

## 模块去留决定

| 模块 | 代码 | 决定 | 说明 |
|---|---|---|---|
| 需求解析 | `core/request_parser.py` | 保留 | 核心入口，已带对话记忆与增量调整 |
| 商品获取 | `core/product_searcher.py` + `core/web_scraper.py` | 保留 | 数据真实性生命线，抓取规则刚理顺 |
| 推荐决策 | `core/recommender.py` | 保留现状先用 | 刚完成 TOP-N 动态条数 + 对话记忆升级，先自用攒痛点再改 |
| 购物车 | `core/virtual_cart.py` | 保留 | 收藏 + 降价监控，轻量实用 |
| 订单物流 | `core/order_manager.py` | 保留现状 | 主流程「买第X款」的自然终点 + 演示闭环；自用时当购物记录本 |
| 偏好档案 | `core/profile_module.py` | 保留 | 推荐打分的永久依据，自用核心 |
| 用户中心 | `core/user_center.py` | 保留 | 刚建成的基础设施 |
| 跨模块/基础设施 | ai_client / web_server / 会话 / 配置 / 前端 | 归全局 | 由已有 `全局/` 承接 |

**结论：8 个业务模块全部保留现状，无移除、无新增。**

## docs/project/ 子文件夹结构（本轮建立）

- 新建 7 个模块文件夹：`需求解析/` `商品获取/` `推荐决策/` `购物车/` `订单物流/` `偏好档案/` `用户中心/`，各含骨架 `design.md`（一句话定位 + 正文待开发者填写；design.md 由开发者主导，AI 不代写正文）
- 既有 `全局/` 不动（跨模块 spec/plan 与 archive/）
- 文档机制不变：开发者写 design.md → AI 生成 designs-specs.md → 开发 → 落地/废弃的 spec/plan 移入所属模块 archive/

## 候选池（未立项，勿直接实施）

自用攒出真实痛点后再立项，届时走 优化建议区 / 新功能开发区：

- 推荐五维权重按需求动态调整（用户说「质量优先」时调权）
- 真实快递单号查询（接公开快递查询 API，与模拟物流互补）
- 图片多模态增强（找同款精度、多图对比体验）
