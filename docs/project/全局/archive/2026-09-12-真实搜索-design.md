> 创建于 2026-09-12（开发者指令发起，AI 起草）
> 修订于 2026-09-12 01:24：纳入同日 GitHub 调研结论——新增「Patchright 反拦截基座」与技术选型决策记录（详见「背景与决策」）
> 状态：已实施（2026-09-12 自测/demo 回归通过）
> **补充事实（实施中发现）**：京东搜索未登录时**整页渲染为登录页**（spec 原平台表「未登录可搜」已过时）——京东/淘宝搜索均强登录，扫码登录窗口机制为必经环节
> **Plan:** [2026-09-12-真实搜索-plan.md](./2026-09-12-真实搜索-plan.md)

## 背景与决策

- 开发者目标 UX：输入「通勤运动鞋 200-400」→ 直接返回 3-5 条跨平台带图商品，再走现有打分 TOP3；不再强制用户粘贴链接。
- 前任「禁止自动批量搜索商品列表/禁止遍历搜索结果页」规则经**当前开发者明示解除**（2026-09-12）；联盟 API 申请未通过；云端抓取方案已否决（机房 IP/无会话/不适合风控型电商）。
- 登录态方案参照 bilibili-summary-assistant 的理念：**用户自己登录（扫码），程序只复用会话，绝不过手账号密码**。
- **反拦截技术选型**（GitHub 调研 2026-09-12）：采用 **Patchright**（[Kaliiiiiiiiii-Vinyzu/patchright-python](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright-python)，Playwright 的免检测补丁版）作为反检测基座。理由：被拦截的根因是原版 Playwright 的 CDP 指纹泄露（如 `Runtime.enable` 可被页面探测），行为级伪装（随机延迟/慢速滚动）无法解决；Patchright 在驱动层修补指纹，且为 drop-in 替换——只改 import，现有 `_launch_browser`（真实 Chrome + 持久化 profile + 有头）即为其官方推荐的最佳实践，无需结构性改动。**已否决项**：browser-use（自然语言全自动 agent，每步依赖 LLM 决策，违反「LLM 仅增强」红线且 token 消耗大）、DrissionPage（需重写整个抓取层，迁移成本高）、invisible_playwright（Firefox 指纹路线，与现有 Chrome 登录态 profile 不兼容）、playwright_stealth（仅参数级伪装，强度弱于驱动级修补的 Patchright）。

## 新的抓取克制条款（替代旧规则）

- 仅在**用户主动发起购物需求**时搜索；每次需求每平台限量抓取结果页**前 ≤10 条**卡片；
- **不翻页、不遍历**搜索结果；不做定时/后台轮询搜索；
- 必须使用真实有头浏览器（现有 `_launch_browser`：真实 Chrome 优先 + 持久化会话 + 随机延迟 + 慢速滚动）；
- 登录墙/验证码：暂停交还人工（复用「继续抓取」机制），不绕过任何风控；
- 搜索拿不到的字段留空，绝不编造；`data_source` 如实标注「真实」。
- 反检测仅限**指纹规避层面**（修补自动化框架自身指纹，Patchright）；不绕过任何验证码/风控，遇登录墙照旧暂停交还人工。

## 功能设计

### 1. web_scraper 层：`search_platform(keyword, platform, max_results)`

- 平台常量表：搜索 URL 模板 + 结果卡片 selector 候选列表（名称/价格/图片/店铺/销量/链接），selector 全部**多候选防御式**，取不到留空；
- 复用 `_launch_browser`（真实 Chrome/持久化会话）、`_goto_with_retry`、`_random_delay`、`_slow_scroll`、`_detect_block`；
- 登录墙/验证码：返回 `need_human=True` + block_reason 含「继续抓取」（与详情抓取同契约）；
- 返回结构：`{"platform", "cards": [{name, price, image, seller, sales, url}], "block_reason", "need_human"}`；
- 每平台一个浏览器会话顺序执行（不并发，克制）；
- **反拦截基座（修订新增）**：`_launch_browser` 的导入走兜底链——`patchright.sync_api` 优先，缺失则回退原版 `playwright.sync_api`（可选依赖红线：缺 patchright 不影响启动）；遵循 Patchright 最佳实践——真实 Chrome channel 优先、有头、持久化 profile、真实 channel 下不覆盖自定义 UA（现有实现天然满足）；搜索卡片 selector 候选可参考 [MarketSpider](https://github.com/zhangjiancong/MarketSpider)（淘宝/京东/1688 关键词搜索爬虫）的历史 selector 作为补充候选源。

### 2. product_searcher 层：`search_real(...)`

- 搜索卡片 → 现有 `Product`（`_build_product_from_card`）：名称/价格/图片/店铺/销量/source_url 入结构，评价等详情字段留空（卡片层没有就空，绝不编造）；
- `data_source="真实"`；
- 入口 `search_real(keyword, platforms, price_min, price_max, max_per_platform)` 返回 `(products, block_reason, need_human)`。

### 3. shopping_agent 层：新工作流 `_flow_search_and_recommend`

- 意图分流：解析出结构化需求且**无粘贴链接** → 走新流程；有链接 → 原 `_flow_grab_and_compare` 不变；
- 流程：`search_real` → 预算初筛 → 复用 `recommender.recommend_from_products` 打分 → `format_top3` 输出；
- 搜索条数不足（<3）或被登录墙拦截：如实提示（含「可粘贴商品链接补充」的旧路径提示）；登录墙时存 pending，「继续抓取」续跑搜索；
- 输出中每条商品附图片与 `data_source` 标注（前端已有渲染能力，不改前端结构）。

### 4. 非目标（本期不做）

- 拼多多/抖音搜索；搜索结果翻页；后台定时监控降价时自动搜索；
- 前端结构改造（复用现有聊天流与 Markdown 渲染）；
- browser-use 式 LLM 全自动浏览器 agent（决策依赖 LLM，违反 AI 全链路兜底红线）。

## 验收标准

1. `python shopping_agent.py demo` 全量回归通过（Mock 链路不受影响）；
2. 京东：真实关键词搜索返回 ≥3 条带图真实商品，字段无编造（缺的字段为空）；
3. 淘宝：未登录会话触发登录墙时，正确输出「请在弹出的浏览器扫码登录…回复继续抓取」；用户扫码后续跑能拿到结果；
4. CLAUDE.md 与 web_scraper 头部规则已替换为新条款；
5. patchright 缺失时自动回退原版 playwright，`demo` 回归不受影响（可选依赖红线）。
