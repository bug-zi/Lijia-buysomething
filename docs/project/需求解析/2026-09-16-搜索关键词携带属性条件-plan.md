## 现状要点（编码前勘探结论）

- 颜色词在 `_extract_keyword` 被有意剔出关键词（core/request_parser.py:714-718；
  require 追加跳过 :750）——`req.keyword` 恒为纯品类词，本设计**保留**该语义，
  颜色改在搜索时拼入查询串。
- 两处搜索点：`_flow_recommend`（shopping_agent.py:484-486，`keyword = req.keyword
  or req.category` + 尺码后拼）；增量替换 `_slot_pick`（shopping_agent.py:595-597，
  只取 `slot_old.category or slot_req.keyword or slot_req.category`）。
- `_apply_hard_filters`（shopping_agent.py:702）颜色 OR 语义 + 未标注颜色候补计数，
  **原样不动**——查询串带颜色只提召回，正确性仍由硬过滤保证。
- `_COLOR_WORDS` 平面色表在 core/request_parser.py:76（本模块自持，无新依赖）；
  `_clean_delta_keyword`（shopping_agent.py:902）的品类词保护**保留不动**。
- shopping_agent.py:21-23 已从 request_parser 导入多个符号，新增导入
  `compose_search_query / validate_search_query` 零循环导入风险。
- LLM 解析 sys_prompt 在 core/ai_client.py:466-486（`max_tokens=700`，加一行字段
  说明余量充足）；`_merge_llm_json` 在 core/request_parser.py:801。
- 「意图理解与按需搜索」实现已在工作区落地（`_flow_adjust_replace`、intent 路由
  就绪），本修复叠加其上，`test_intent_routing` 须照常回归。

## T1 core/request_parser.py — 字段、校验器、组装器

- `ShoppingRequest` 增加 `search_keywords: Optional[str] = None`（置于 `intent`
  字段后；None=无 LLM 产出，搜索时由组装器现场拼）。
- 模块级 `validate_search_query(q) -> Optional[str]`：空白归一后判——空/超 24 字符、
  「第X款」指代、否定词（不要/避开/别要/讨厌/避雷/不想要）、预算碎片（预算/升到/
  加到/提到/以内/以下/以上/左右/封顶）、裸数字金额碎片 → None；通过返回归一串。
  **注意放行「42码」类尺码数字**（数字判定须排除「码」前缀形态）。
- 模块级 `compose_search_query(req, base=None) -> str`：基底
  `base or req.keyword or req.category or "商品"` → 拼「N码」→ 依次追加 require_tags
  中命中 `_COLOR_WORDS` 的颜色词（rstrip("的")、去重保序、全量拼入）→ 整串过
  `validate_search_query`，None 则降级为过校验的纯基底。非颜色属性不拼。
- `_merge_llm_json` 捕获 `search_keywords`：字符串且非空才 `validate_search_query`
  后写入（非法→None），规则层不产出该字段。
- 修订 :714-718 与 :750 注释：「颜色不进 req.keyword 字段；由 compose_search_query
  在搜索时拼入查询串」。
- 自测：校验器拒收矩阵 + 组装器拼词断言。

## T2 core/ai_client.py — schema 加一字段

- `parse_shopping_request_with_llm` sys_prompt 必含字段列表增加：
  `search_keywords: string|null  最适合放进电商搜索框的完整查询串（品类词+可搜正向
  属性如颜色/透气/轻便）；严禁包含否定词（不要X）、预算数字、条数、「第X款」指代；
  没有把握就填null`。
- 其余（函数签名、调用次数、超时）一概不动。

## T3 shopping_agent.py — 两处搜索点接入 + 合并防陈旧

- 导入 `compose_search_query, validate_search_query`（自 request_parser）。
- `_flow_recommend` :484-486 替换为：
  `keyword = (validate_search_query(req.search_keywords) if req.search_keywords
  else None) or compose_search_query(req) or "商品"`；原尺码后拼两行删去（组装器
  已含尺码）。失败/如实告知文案沿用同一 `keyword` 变量，自动展示实际下框查询串。
- `_slot_pick` :595-597 替换为：
  `kw = compose_search_query(slot_req, base=(slot_old.category or slot_req.keyword
  or slot_req.category)) or "商品"`；`_pref_key` 颜色命中优先排序**保留**。
- `_merge_request` :925 后增加：
  `merged.search_keywords = validate_search_query(delta.search_keywords) if
  delta.search_keywords else None`——**不沿用 base**（颜色条件已变，旧串作废，
  搜索时由组装器基于 merged 现场重拼）。

## 不做（YAGNI）

- 不做零结果自动去色重搜（方案 C，列为后续增强候选，不立项）；
- 不扩充颜色词表（香槟色等冷门色维持现状）；
- 非颜色属性（透气/轻便）规则路径不拼入——仅 LLM search_keywords 路径可携带；
- 不改前端 `index.html`；不新增 LLM 调用次数（复用既有 parse 调用）。
