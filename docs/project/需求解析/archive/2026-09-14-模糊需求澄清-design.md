# 模糊需求先澄清再检索 — 设计文档

> 创建于 2026-09-14。来源：问题疑惑区第4轮条目1（「想买个杯子」直搜不追问）。
> 决策记录：开发者选定「一轮式可跳过追问」+「静态表+中性兜底」（AskUserQuestion，2026-09-14）。

## 1. 问题与根因

用户输入「想买个杯子」等「有关键词但信息稀疏」的需求时，系统直接搜索。根因：

- 现有澄清闸 A（shopping_agent.py:188）：仅当品类与关键词**全缺/泛词**才启动品类问答；
- 现有澄清闸 B（shopping_agent.py:191）：`needs_clarify` 只在 4 个固定品类（连衣裙/运动鞋/耳机/手机）缺预算时标记；
- 「杯子」关键词非泛词、又不在品类表 → 两道闸都不拦 → 直搜。

## 2. 方案总览：维度完整度门控（一轮式可跳过）

解析完成后计算核心维度缺失数，缺 ≥2 维则**一轮式追问**（可跳过），答完无论补全与否都继续检索。

### 2.1 核心维度定义（新增于 RequestParser）

| 维度 | 缺失判定 | 追问内容 |
|---|---|---|
| D1 预算 | `price_min` 与 `price_max` 均为 None | 预算大概多少（附档位：100以内/100-300/300-800/800-1500/1500以上） |
| D2 用途/场景 | `purpose` 为空 | 什么场景用（如自用/送礼/办公/通勤…） |
| D3 品类关键属性 | `require_tags` 为空 且 命中属性表或未知品类 | 按品类定制问法（见 2.2） |

规则：
- 档案 `budget_max` 自动补入 `price_max` 时视为「预算不缺」（已有默认，不再追问）。
- `needs_clarify` 字段承载三维度缺失问句（替换原「仅4品类查预算」逻辑）；仅剩 D1 缺失时维持现状——直搜+预算小提示。

### 2.2 品类关键属性静态表 `_CATEGORY_ATTRS`（request_parser.py）

| 品类/关键词 | 追问问法 | chips 建议 |
|---|---|---|
| 杯子/水杯/马克杯/保温杯 | 材质（玻璃/陶瓷/不锈钢/塑料）？容量（350ml/500ml…）？ | 玻璃、陶瓷、不锈钢、500ml |
| 连衣裙/裙子 | 什么场合穿（通勤/约会/日常）？偏好风格或版型？ | 通勤、法式、宽松 |
| 运动鞋 | 什么类型（跑鞋/板鞋/篮球鞋）？什么场景穿？ | 跑步、日常 |
| 耳机 | 头戴还是入耳？需要降噪吗？ | 降噪、入耳 |
| 手机 | 品牌或系统有偏好吗？主要用来做什么？ | 苹果、安卓、游戏 |
| T恤 | 偏好什么风格/版型？纯棉可以吗？ | 纯棉、宽松 |
| 未知品类（兜底） | 有什么具体要求吗（材质/颜色/规格等，可跳过）？ | 直接搜 |

- 命中规则：`category` 或 `keyword` 归一化后包含表中关键词（如「买杯子」keyword=杯子）。
- 纯规则实现，零失败面；LLM 不参与门槛判定（AI 兜底红线），仅按现有 schema 增强 `use` 等字段值。

### 2.3 门槛与交互（shopping_agent.py）

- 触发条件（替换原闸 B 的「≥2 追问」消息）：
  - 有关键词或品类（非泛词）、非 `is_adjustment`、非 `target_rank`、不在既有澄清/问答态；
  - `len(missing_dims) >= 2`。
- 追问消息模板（一条问全，规则模板生成）：

  > 「杯子」想帮你选得更准，确认 {N} 点：
  > 1. 预算大概多少？（100以内 / 100-300 / 300-800 / 800-1500 / 1500以上）
  > 2. 有什么具体要求？（材质：玻璃/陶瓷/不锈钢；容量：350ml/500ml…）
  >
  > 一次答完即可，例如：「100以内，玻璃的，办公室喝水」。回「**直接搜**」就按当前信息搜。

- chips：预算五档 + 品类属性选项（取表）+ 「直接搜」。
- **一轮即止**：应答并入原需求重解析后直接进推荐流程，即使仍有缺失（此时如有剩余 D1 缺失沿用小提示）。跳过词沿用 `_CLARIFY_SKIP`（随便/都行/直接搜…）。
- 缺 1 维：保持现状（直搜 + 「暂未识别到预算」类提示）。

### 2.4 状态机

- 复用 `_pending_clarify`，新增 `{"stage": 3, "text": 原始输入, "dims": [...]}`；`_flow_clarify_answer` 增加 stage 3 分支：skip → 原需求直搜；否则 merge 后直搜。stage 1（品类）/ stage 2（预算）流程不变。
- 会话态持久化沿用现有机制（stage dict 增加键向后兼容）。

## 3. 评价区去凑数话术（同轮一并修）

根因：recommender.py:463-471 硬凑「优点≥3、缺点≥2」；真实搜索卡片大多无评价明细，填充话术属编造，违反数据真实性红线；好评率默认 0.95 在无数据时也展示。

修复（recommender.py `format_top`）：
- 「优点（≥3）/缺点（≥2）」标题改「买家好评/买家差评」，不承诺条数；有几条真评价显几条。
- 无 good_points → 该行显「未抓取到买家评价数据」；无 bad_points：有评价数 → 「已抓取的评价中暂未见明显差评」，无评价数 → 「未抓取到评价数据」。
- `_core_highlights`（属性衍生）独立成行「**商品卖点**」，不再冒充买家好评。
- 好评率/总评/带图追评统计行仅在 `review_count > 0` 时输出。
- index.html:2446 前端兜底「暂无明显差评」同步改为如实表述。
- 演示数据评价齐全，展示不变；**不**补抓详情页评价（越「抓取克制」红线，不自作主张扩权）。

## 4. 影响面与兼容

- `needs_clarify` 内容变化：更新相关断言/回归用例；session 存档兼容（字段同名）。
- 调整类（「换个红色的」）、买第X款、澄清态、自由问答等早退路径不受影响。
- 无 emoji；消息出口净化工序不变。

## 5. 测试与验收

断言脚本（仿现有模式，不进真实搜索链路）：
1. 缺失维度判定矩阵：杯子/连衣裙/带预算/带用途/带属性/未知品类组合。
2. 一轮澄清流：skip → 原需求直搜；正常应答 → merge 后直搜；不再二次追问。
3. 门槛豁免：调整类、买第X款、缺1维直搜+提示。
4. recommender 渲染：有评价/无评价/有差评无好评率 三态快照断言；无 emoji 断言。

真机冒烟（开发者执行）：「想买个杯子」→ 追问；答「100以内 玻璃 办公室」→ 搜索；「直接搜」→ 搜索；「连衣裙 预算200」→ 仍追问场合/风格两维（预算已给、用途+属性缺）；「买个玻璃杯子 通勤」→ 直搜+预算提示；演示模式推荐卡评价区文案检查（旧凑数话术不再出现）；重启服务后旧会话澄清态可恢复。

## 迭代记录：追问表单化（2026-09-14 晚，开发者真机实测反馈）

实测确认链路生效后提出四项要求：①点选不应即提交，要多选；②选项按问题分组不混排；③每题带「其他」自填 + 末尾补充栏；④问题扩到 4~6 个——关键问题给选项、次要问题只给方向由用户自行补充。

落地（详见 `docs/log/260914.md` 同日「澄清追问表单化」节）：

- `request_parser.py`：`_CATEGORY_QUESTIONS` 问题集（每品类 core_attrs 1~2 问 + extra 恒 2 问选填方向 + 预算/用途通用两问 = 恒 4~6 问）+ `clarify_form()` 结构化表单产出；`missing_dims()` 收敛为门槛判定。非预算题选项禁含数字（防 `_parse_budget` 误解析）。新增手机壳品类问题集（机型自填+材质多选）。
- `shopping_agent.py`：追问消息由表单驱动（文字保底），chips 置空防「点即发送」；新增 `pop_clarify_form()`；缺预算提示改 `missing_dims()==["budget"]` 判定。
- `web_server.py`：`/api/chat` 响应加 `clarify_form` 字段。
- `index.html`：分题表单（选项 chips 点选只勾选、单选互斥多选叠加、每题「其他」输入框、补充栏 textarea、「提交并搜索/直接搜」统一提交）；提交合成一句自然语言走原 stage-3 合并直搜链路。
