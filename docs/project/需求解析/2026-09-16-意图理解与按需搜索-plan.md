# 意图理解与按需搜索 — 实施计划

> 创建于 2026-09-16。
**Spec:** 同目录 `2026-09-16-意图理解与按需搜索-design.md`（方案 A 已选定 + 4.4 增量替换修订）。

## 现状要点（编码前勘探结论）

- LLM 解析 schema **已有** `intent` 字段（core/ai_client.py:483，枚举 demand/search/profile/order/query_order/logistics/aftersale/other）——在其上扩 `qa` 枚举，不另起炉灶。
- `recommender.recommend_from_products` 会整体覆写 `_last_products/_last_scores`（core/recommender.py:384）——增量替换不得走它，取 top-1 用 `score_product` 自行排序。
- `get_last_product(rank)` 已存在（core/recommender.py:651，`_flow_confirm_buy` 在用）——只补 `replace_last_product`。
- `format_top` 的「TOP最优化」标题写死（core/recommender.py:399）——加可选 `title` 参数供增量替换整表重出时换头。
- `temp/test_adjust_negation.py` 用例 2/3 断言的是**旧的全量重搜行为**，按 4.4 修订期望（行为变化是设计使然，解析层三项根因断言全保留）。

## T1 core/request_parser.py — intent 字段与规则速判

- `ShoppingRequest` 增加 `intent: Optional[str] = None`（值域 `buy_rank/qa/adjust/new_search`，None=灰区待终判）。
- 模块级 `QUESTION_RE`（疑问信号，取自 shopping_agent._QA_QUESTION_RE 同式）与 `NEW_DEMAND_RE`（新需求硬标志：购买动词开头，或「推荐/搜一下/找/来点/有没有/想买/求」+品类词命中）。
- `_parse_rules` 末尾规则速判：`rank_buy_intent→buy_rank`；硬标志→`new_search`（压过疑问信号）；疑问信号→`qa`；调整标记+条件变更→`adjust`；全无→None。
- `_merge_llm_json` 捕获 LLM `intent=="qa"`：仅当规则速判为灰区（None）时采纳为 `qa`，不确定不覆盖规则结论（LLM 终判只裁灰区）。
- 自测：速判矩阵断言（对比句/买第X款/硬标志问句/纯调整）。

## T2 core/ai_client.py — schema 扩枚举 + QA prompt 增强

- `parse_shopping_request_with_llm` 的 intent 枚举说明追加 `qa=基于当前会话推荐商品的提问/对比/评价咨询（不搜新商品）`，并补一句判据：用户提到「第X款/上一轮/刚才那些」且在提问 → qa。
- `answer_free_question_with_llm`：点名「第X款 vs 第Y款」时逐项对比价格/评分/适用性并给结论+理由；NEED_SEARCH 判据收紧为「明确要求搜索/推荐新商品」才输出。

## T3 core/recommender.py — 槽位写表访问器

- 新增 `replace_last_product(rank: int, product, score)`：1 起始位次原位替换 `_last_products[rank-1]` 并同步 `_last_scores`；越界静默忽略（返回 False）。
- 新增 `last_products()` 返回当前表快照（列表浅拷贝）。

## T4 shopping_agent.py — 意图分派路由 + 问答一等分支 + 增量替换

- 类属性 `_QA_QUESTION_RE`/`_BUY_INTENT_RE` 改为引用 request_parser 同一正则对象（单一来源）。
- 4) 段重排（design 4.2）：4.1 强意图短路不动 → 4.2 `intent==qa` 进 `_flow_context_qa`（一等分支，永不落搜索）→ 4.3 adjust_like 且有上轮：`intent==adjust` 且 `target_rank` 命中 `get_last_product` → `_flow_adjust_replace`，否则原合并+`_flow_recommend` → 原 4.2.5 灰区泛词 QA 保留 → 4.4 澄清门控 → 4.5 推荐。
- `_flow_context_qa(text)`：材料（last_recommendation_brief/历史）缺失 → 直接兜底；`_try_free_qa` 改造为返回 `(status, text)`（ok/need_search/none）：need_search 且带新需求硬标志 → 重判转 new_search/adjust 既有流程；否则视为 LLM 误判 → 失败兜底。失败兜底：`_extract_compare_ranks`（取句中前两个「第X款」）成功 → 数据对比卡（名称/平台/到手价/总分/分项，缺失标「未抓取到」+「AI 答疑暂不可用」附注）；提取不出 → 如实告知无推荐记录。绝不搜索。
- `_flow_adjust_replace(text, req, cancel_check)`（design 4.4）：定位槽位 → `_merge_request` 得 merged 并同步 `_last_request` → 以被指商品 `category`（+尺码）定向限量搜索 → `_apply_hard_filters(merged)` 后剔除表内已有 pid → `score_product` 排序取 top-1 → 零结果如实告知（表不变）。保留槽位复验用 `kept_req`（merged 的价格/平台/尺码 + **base** 的 require/exclude——delta 属性仅作用于被指槽位），违规槽位连带替换并逐款说明。原位 `replace_last_product` 后整表 `format_top(title=...)` 重出，尾注注明第X款新搜替换/其余保留上一轮/连带替换说明。need_human（登录墙）沿用「继续抓取」话术；无上一轮或越界 → 落回全量流程（不崩溃）。
- `format_top` 加 `title: Optional[str] = None` 参数（默认行为不变）。

## 不做（YAGNI）

- 不做完整对话状态机；不扩权补抓数据；不改前端 `index.html`；
- 多槽位（「第一、二款都换」）本轮不做，解析层单 `target_rank` 不动；
- 不新增 LLM 调用次数（intent 复用既有解析调用）。
