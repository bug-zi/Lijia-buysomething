## 冗余提示语收纳：小贴士组件（优化建议区第 9 轮）

> 创建于 2026-09-15 22:35

**需求**：开发者指出前端多处提示语直接平铺在页面里很占空间（点名两处：用户中心头像说明、AI 查询浏览器窗口说明），要求排查全部冗余提示语，收进「类似小贴士的小组件图标」，点击才查看说明。

**排查结果**：全文件扫描 `.help`/`.sub`/说明性文本，确定 14 处长提示语收纳入小贴士（用户中心 7 处含动态渲染的浏览器窗口说明、购物清单 1、虚拟购物车 1、TOP3 推荐 1、配置库 5）；保留的短提示：用户中心 ID 行（含动态 uid，本身很短）、新手引导文案（一次性引导流，非冗余）、登录态卡片动态状态行。

**实施**（仅改 `index.html`，后端零改动）：

- **组件**：`.hint-tip` 容器 + `.tip-btn`（Material Symbols `info` 圆形图标钮，24px，hover/展开态主题色 `--primary` + `--primary-soft`）+ `.tip-pop-src`（hidden 存说明原文，支持 `<b>/<code>/<br>` 富文本）。
- **单例浮层** `#tip-float`（`.tip-float`，`position:fixed` + JS 按 `getBoundingClientRect` 定位在图标下方 8px，右缘越界翻转为右对齐、下方越界翻到图标上方，宽 `min(380px, 100vw-24px)`）。采用单例而非各实例内嵌 popover 的原因：`.card` 有 `backdrop-filter` 会创建层叠上下文，内嵌浮层会被后续兄弟卡片盖住；单例挂在文档层彻底绕开。z-index 900（低于弹窗 1200/引导 1000/toast 999）。
- **交互**：`toggleTip(btn)` 开/关切换；点浮层外部、Esc、窗口缩放、任意滚动（capture）均关闭；同一图标二次点击关闭。内容从 `tip-pop-src` innerHTML 复制（静态自有文案，无注入面）。
- **样式全走主题变量**（`--card/--border/--text-*/--primary/--shadow`），四皮肤 × 深浅模式自动适配，无 emoji（图标用 Material Symbols，符合红线）。
- **收纳明细**：账户信息隐私说明、头像自定义说明（移至性别/保存行尾）、界面偏好保存说明、主题色说明、档案保存说明、录入向导说明、购物清单用法、购物车定位说明、TOP3 打分说明、配置库增强说明、API Key 服务商列表（移至 label 旁）、安全说明 4 条列表（整段收纳，保留标题行）、网站登录态使用说明 + 登录有效期说明（合并为一个浮层内两段）、`renderUcPrefs` 动态渲染的 browser_popup 说明（模板字符串内联 hint-tip）。

**验证**（Chrome + 8765 在跑服务，未进真实搜索链路）：

- 14 个实例 DOM 计数正确；逐一弹出内容抽查与原文一致。
- 关闭逻辑：点外部 / Esc / 同图标二次点击 / 滚动全通过；控制台零错误零警告。

## 「取消并退回编辑」移位至用户气泡旁（优化建议区第 10 轮）

> 创建于 2026-09-15 23:43

**需求**：开发者提出对话购物中的「取消并退回编辑」按钮应放在用户输入消息的组件框边上，而不是当时的位置（打字动画下方的独立 AI 气泡行）。

**实施**（仅改 `index.html`，后端零改动）：

- `appendCancelRow(onCancel)` 改签名为 `appendCancelRow(userEl, onCancel)`：不再创建独立的 AI 消息行（`#chat-cancel-row` 连同 AI 头像、气泡壳一并删除），改为创建一枚 `.chip .cancel-send-btn` 按钮追加进本条用户消息行元素。
- 位置原理：`.chat-msg.user` 为 `flex-direction: row-reverse`（头像在最右），按钮作为最后一个子元素天然落在用户气泡左侧，`gap:10px` 与气泡自然间距；新增一行 CSS `.chat-msg.user .cancel-send-btn { flex-shrink: 0; align-self: center; }` 保证按钮不被压缩、相对气泡垂直居中。
- `removeCancelRow()` 改为按类名清除 `#chat-messages` 内所有 `.cancel-send-btn`（正常返回/出错/取消三条路径照旧调用）；取消路径下按钮本就在用户气泡元素内，随 `userEl.remove()` 一并撤回，互不冲突。
- 样式完全复用既有 `.chip`（主题变量驱动），四皮肤 × 深浅模式自动适配，无新增配色、无 emoji。

**验证**（Chrome + 8765 在跑服务，纯前端模拟未进真实搜索链路）：

- 取消链路：单轮干净环境下点击按钮 → 打字动画移除、按钮移除、用户气泡移除三断言全过（此前一次 typing 残留误报为测试脚本自身重复 appendTyping 所致，清场重验通过）；`removeCancelRow()` 在无按钮时空转不报错。
- 正常返回/出错路径的 `removeCancelRow()` 调用点逐一核对，历史会话渲染不受影响。
- 控制台零错误零警告；测试标签页已关闭，未动用户已开页面。

## 「买第X款」误触发重新搜索：强意图短路修复（问题疑惑区第 8 轮）

> 创建于 2026-09-15 23:52

**问题**：开发者按《2026-09-15-全功能演示操作手册》实测——先搜出 3 双跑鞋，再输入「买第2款」，预期走「订单草稿 + 支付风险提醒」，实际却重新搜索了三双鞋。

**根因**：规则引擎对「买第2款」本有 `buy_first` 短路（`request_parser._parse_rules` 开头命中即只填 `target_rank` 返回），路由层 4.1 也要求「其他字段全空」才走下单。但 `parse()` 在规则之后还有两步增强：① LLM 需求解析的 prompt 把 `query`/`category` 设为**必填 string**，LLM 面对上下文（历史里有跑鞋需求）必然脑补出 query=跑鞋、category=鞋、budget_max=300 等字段合并进结果；② 档案 `budget_max` 默认预算回填。两步污染后「其他字段全空」条件失效，改道 4.4 推荐搜索。离线（LLM 关闭）复现不了，故前几轮测试没暴露。

**落地**（`core/request_parser.py` + `shopping_agent.py`）：

- `ShoppingRequest` 新增 `rank_buy_intent` 字段：`buy_first` 短路命中时置 True（纯规则判定，LLM 不参与）。
- `parse()` 在规则解析后**立即短路返回**：命中强意图时跳过 LLM 增强与档案预算回填——该输入的目标已完全确定（上次推荐第 X 款），任何「增强」只会引入污染。
- 路由 4.1 改为 `target_rank 非空 且 (rank_buy_intent 或 其他字段全空)`：显式接受强意图标记；「LLM 单独识别出 target_rank 且无其他字段」的旧路径保持不变。「第2款太宽松，换修身的」类修正意见（target_rank 只是句中提及、其他字段非空）仍走调整路径，不被劫持。

**验证**（离线断言，不进真实搜索链路）：

- 新增 `temp/test_buy_rank_intent.py`：装一个会按历史脑补 query/品类/预算的假 LLM 解析器复现真机污染路径——「买第2款」→ LLM 0 次调用、0 次搜索、正确产出订单草稿 + 支付风险提醒，「确认」后进入下单模拟；正常新需求（买跑鞋）照常搜索；「第2款太重了，换更轻便的」仍走调整重搜。4 项全过，可复跑。
- 回归：`test_review_honest.py`、`test_t4_parser.py` 全过；纯规则探针确认档案有预算（budget_max=300）时短路结果零污染（keyword 空、price_max None）。
- `py_compile` 两文件通过。
- 已知过时项（非本轮引入）：`temp/test_dims_clarify.py` 第 1 项断言题序（预算第一题）系第 4 轮静态表时代旧断言，第 7 轮问卷改 AI 现场生成后题序已变，该脚本本轮未改（`test_food_clarify.py` 静态兜底断言仍全过）。

**真机冒烟清单**（需重启服务；重启前 `netstat -ano | findstr :8765` 确认旧进程已退）：

1. 新会话输入「买一双跑鞋，日常运动穿，透气轻便的，预算300以内」→ 正常搜索 3 双；
2. 输入「买第2款」→ 应出现订单草稿核对信息 + 支付风险提醒（不再重新搜索）；
3. 回复「确认」→ 下单流程模拟（订单号），订单/物流可查；
4. 回归：「第2款太重了，换更轻便的」→ 应重新推荐而非下单。

## 多账户机制：注册/登录/数据全隔离（新功能开发区第 2 轮）
