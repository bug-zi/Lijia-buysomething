# 260916 开发日志

## 新账户引导修复（服务端标记）+ 账户数据 GitHub 隔离补漏

> 创建于 2026-09-16 00:22

**背景**：开发者实测多账户机制（注册「张三」新账户）后反馈两问题：① 新账户进入没有弹新手引导；② 配置库里常用购物平台登录信息仍在（同机共享是否正常？换电脑/同伴 clone 代码后是否会看到）。另确认一个关键问题：代码上传 GitHub、同伴 clone 到自己电脑后登录「bug子」账户，能看到本机的使用记录和平台登录配置吗？

**根因排查**：

1. **新账户无引导 = 真 bug**。引导标记 `sa_onboarded` 存在浏览器 localStorage（浏览器级、不分账户）；「退出登录」只清 token 不清引导标记，`onAuthed` 里换账户清理逻辑又因 `sa_username` 已被清空而短路跳过——同浏览器新注册的账户继承了上个账户「已引导」状态。
2. **平台登录信息同机共享 = 设计如此**。`login_state.json`（扫码登录态）与 `.browser_profile/`（浏览器配置文件）是**机器级**数据，按多账户设计明确保持全局共享（抓取用登录态与账户体系无关）。换新电脑天然不存在。
3. **GitHub 隔离有漏网**。核对 `.gitignore`：8 类按账户隔离的数据文件中 7 类已被既有规则覆盖（gitignore 无斜杠模式匹配任意层级，`accounts/<用户名>/` 下的同名文件同样被忽略），但 **`shopping_list.json` 漏配**（会连购物清单一起上传）；**`accounts.json`（账户表：用户名/邮箱/加盐密码哈希/持久登录 token）也未忽略**——token 上传等同把有效登录凭据放进仓库。

**落地**：

- **`index.html`**：
  - `doLogout()` 退出时补清本账户本地缓存（`sa_active_session`/`sa_uc`/`sa_onboarded`）并 `setSaToken("","")`；
  - 「已引导」升级为**按账户存服务端**：`markOnboarded()` 双写（localStorage 兜底 + `POST /api/usercenter {onboarded:true}`）；`onboardNext` 完成态与 `onboardSkip` 均改走 `markOnboarded()`；
  - `maybeOnboard()` 改为先 `loadUserCenter()` 再判断——服务端 `_uc.onboarded` 为真或本地标记存在则不弹，否则弹引导；`bootAfterAuth` 里原独立的 `loadUserCenter()` 并入 `maybeOnboard`（消除双请求）。
- **`core/user_center.py`**：`DEFAULTS`/`load()` 增加 `onboarded` 布尔键（缺省 False，旧数据自动补全）；`save()` 白名单新增 `onboarded`（仅接受严格 `True`）。
- **`.gitignore`**：补 `shopping_list.json`、`accounts.json`、`accounts/` 三行——账户数据（含账户表）从此不随仓库走，每台电脑各自注册、各自隔离。

**验证**（8902 临时服务 + 临时数据根，不碰真实数据与 8765）：

- `python core/user_center.py` 自测通过（默认值/白名单/部分更新/uid 稳定/无敏感字段）。
- 浏览器走查四场景：注册「丙三」→ 引导弹出；跳过引导 → 退出 → 重登「丙三」→ **引导不再弹**（服务端标记生效）；退出 → 注册「丁四」→ 引导重新弹出（原 bug 修复）；全程控制台零错误零警告。
- 回归：`_t9_accounts_test.py` 全过（401/注册校验/首账户迁移/双账户隔离/登出重登/Key 路径隔离）。
- 测试后清理：临时服务已停、8901/8902 端口无残留、临时脚本与 playwright 快照已删。

**GitHub/多电脑结论（答复开发者）**：修复后 push 到 GitHub 的内容不含任何账户数据与登录凭据——同伴 clone 后是全新空白环境，需在自己电脑上注册自己的账户；即使注册同名「bug子」也是空档案、空订单、未配置平台登录态。`mock_products.json`（演示数据）随仓库共享属有意保留。

**注意（需开发者操作）**：8765 常驻服务仍是旧进程，重启后本批修复才生效；重启后「bug子」首次进入**不会**重弹引导（浏览器里的旧标记仍作兜底），历史账户的「已引导」会在其下次退出→重登后自动写入服务端。
