# 260914 开发日志

## 对话窗口渲染优化：消除「生硬/被截断/不顺畅」（开发者口头需求）

> 创建于 2026-09-14 00:05

**需求**：开发者反馈「对话购物和 AI 对话的窗口看着很生硬，有种被截断的感觉，看着不顺畅」。分析定位出四个根因，经确认后实施 P1+P2 优化，仅改 `index.html`（前端渲染层），后端零改动。

**根因分析**：
1. **表格横向截断**（截断感最大来源）：`.chat-bubble table` 的 `display:block + white-space:nowrap + overflow-x:auto`，叠加气泡 `max-width:78%`——商品对比表（本产品高频输出）必然放不下，右侧列被硬切 + 出横向滚动条。
2. **换行处理错乱**（断句感）：气泡 `white-space:pre-wrap` 但渲染器只把 `\n{2,}` 转段落，单个 `\n` 全部变成强制折行，一段话被显示成一行行断句；渲染器在列表/表格/标题前后插入的 `\n` 也变成可见空行，间距忽大忽小。
3. **整条消息包在一个 `<p>` 里**：`<p>` 内嵌 `<h4>/<ul>/<table>` 非法嵌套，浏览器隐式闭合 `<p>`，部分文字落在段落样式外，间距失控。
4. **交互硬切换**：无流式输出（打字动画→整条消息瞬间替换）；`scrollTop=scrollHeight` 瞬移无平滑；`.chat-messages` 挂 `backdrop-filter:blur(12px)` 滚动每帧重绘模糊；图片异步加载撑高内容后不补滚动，最后一条消息下半截留在屏外。

**实施**：
- **表格**（CSS）：去 `display:block/nowrap/overflow-x` 截断模式，改 `width:100%` + 单元格自动换行（`padding:5px 9px`、字号 12.5px、`vertical-align:top`）；AI 气泡放宽 `max-width:min(85%,640px)`（用户气泡保持 78%）。
- **同轮追加（00:19，开发者反馈 AI 输出横向长度仍不够）**：AI 气泡上限 `min(85%,640px)` 再放宽为 **`min(94%,960px)`**。气泡为收缩适应内容布局——实测长内容/宽表格会撑满新上限（8 列大表撑到 949px，即 1047px 聊天栏的 94%，表格 921px 完整无溢出），短回复仍保持紧凑不空旷。
- **换行接管**（renderMarkdown 重构收尾段）：气泡 `pre-wrap` 改 `normal` + 显式 `line-height:1.6`；渲染器改为**空行切段**——块级段（标题/列表/表格/hr 开头）保持原样不包 `<p>`，普通段包 `<p>` 且段内单 `\n` 转 `<br>`；删掉整条包一个 `<p>` 的旧逻辑；恢复 stash 后清理贴着块级标签的多余 `<br>`/`\n`，消除标题、列表上下的多余空隙；入口统一 `\r\n?→\n` 归一化。
- **顺手修两个渲染器潜伏 bug**：① 表格正则 `(?:\|.+?\|\n)+` 要求末行必须有换行符，最后一行数据会被甩在表格外显示成原始竖线（旧代码就有）——改 `\n?` 可选；② 列表正则组内 `\s*` 会吞掉列表前空行破坏切段——改 `[ \t]*`；列表替换末尾补 `\n` 让列表后正文正确成段。
- **滚动与切换**：`.chat-messages` 去 backdrop-filter/半透明（改纯 `--chat-bg`），加 `scroll-behavior:smooth` + 8px 细滚动条；新增 `scrollChat(instant)` 助手（`scrollTo` 显式 behavior 覆盖 CSS），`appendMsg/appendChips/appendTyping` 平滑滚底，**历史会话恢复传 `{instant:true}`**（跳过 fadeUp 动画 + 瞬时滚底，避免几十条消息逐条平滑滚动互相打架）；图片 `load` 后若视口仍在底部附近（<320px）补一次滚动；`removeTyping` 保持瞬时移除（试过 150ms 淡出，会与平滑滚底叠加产生二次跳变，已回退并注释原因）；`prefers-reduced-motion` 下关动画与平滑滚动。

**验证**（Chrome + 8765 在跑服务，未进真实搜索链路、后端零请求）：
- CSS 生效：气泡 `white-space:normal`、滚动区 `scroll-behavior:smooth`、`backdrop-filter:none`。
- renderMarkdown 断言：单换行→`<br>`、空行分段、列表/有序列表/表格/标题/裸链/md 链接/`\r\n` 归一化全过；空文本返回空串。
- 视觉实测：注入 5 列商品对比表样例——表格 611px 完整落在 639px 气泡内，`scrollWidth<=clientWidth` 无横向溢出；段落/列表/加粗分层清晰；自动滚底到位；390px 窄屏页面与气泡均无横向溢出（表格自动换行）；控制台零错误。测试消息仅注入前端 DOM，刷新即清，未触碰会话数据。
- taste_lint 静态扫描：本次改动相关的 FAIL 仅 `pre` 代码块 `overflow-x:auto`（刻意的代码横向滚动区，规则豁免场景）；其余 13 个「固定宽度」FAIL 与 4 个装饰性 WARN 均为全文件既有模式（会话栏 232px、弹窗宽度、背景光斑等），不在本轮范围。

**遗留（如实说明）**：AI 回复仍为非流式（整条返回后一次渲染），流式输出需后端 SSE 配合，本轮未动；对比表在 ≤400px 极窄屏下单元格换行会较挤（可读但不宽裕），如需进一步可做卡片式响应式表格，待开发者定夺。

## 追加：主对话框纵向扩容（开发者反馈视野不够开阔，00:30）

**测量基线**（浏览器实测，视口 679px 样本）：顶栏 56 + 面板 padding 上下 40 = 实际开销 96px，但 `.chat-layout` 写死 `calc(100vh - 130px)` **多预留 34px 纯浪费**（聊天框下方空白）；快速 chips 38px + 输入区 75px；消息区仅剩 435px（占视口 64%）。

**实施**（4 处 CSS，后端零改动）：
1. `.chat-layout` 高度 `calc(100vh - 130px)` → `height:100%`（撑满 tab-panel 内容盒，消灭 34px 浪费；tab-panel 本就 flex:1+min-height:0，百分比高度可解析）；
2. 聊天页专属内边距 `#tab-chat { padding:14px 18px }`（原继承 20px 24px，纵向再让 12px，横向顺带让给内容）；
3. `.chat-input-wrap` margin-top 14→10px；
4. `.topbar` 高度 56→50px（全局，主要受益者是占满视口的聊天页；status 胶囊/图标钮 34px 高仍富余）。

**结果**（同视口复测）：消息区 **435 → 491px（+56px，+13%）**；`unusedBelow` 34→0；body 无滚动溢出；顶栏内容无裁切、其他页签不受影响（订单页正常滚动）；会话侧栏随 chat-layout 同步长高；控制台零错误。恰好开发者正真实使用（10 列真实商品对比表会话），新高度下整表完整可见，属实战冒烟。1080p 全屏下按比例消息区约 **835 → 891px**。

**涉及文件**：`index.html`（`.chat-layout`/`#tab-chat`/`.chat-input-wrap`/`.topbar` 四处 CSS）、本文档。

**遗留（如实说明）**：AI 回复仍为非流式（整条返回后一次渲染），流式输出需后端 SSE 配合，本轮未动；对比表在 ≤400px 极窄屏下单元格换行会较挤（可读但不宽裕），如需进一步可做卡片式响应式表格，待开发者定夺。

## 购物清单（购买前需求池）——新功能落地（新功能开发区第 1 轮）

> 创建于 2026-09-14 00:35

**需求来源**：`docs/project/新功能开发区.md` 待完成区——开发者想要一个存放「想买但还没开聊」商品意向/模糊需求的清单，并疑问是否与购物车重复。brainstorming 对齐结论：**不重复，是上下游**——清单 = 推荐前的需求池（一句话需求即可），购物车 = 推荐后的商品收藏；链路为 清单 → 对话购物 → 购物车 → 订单。设计/计划见 `docs/project/功能模块/购物清单/`（已随落地入 archive/）。

**四项已确认决策**：① 定位购买前需求池（否决购物车扩展方案）；② 双入口（清单页手动 + 对话「记到清单：xxx」）；③ 「去推荐」填入对话输入框**不自动发送**（抓取克制：避免误触真实抓取）；④ 两态生命周期（待处理/已完成，已完成折叠可清空）。

**实施**（5 个任务全过）：
- **数据层** `core/shopping_list.py`（新建）：`ListItem`（id/content/created_at/done）+ `ShoppingList` + **模块级单例**（需求池跨会话共享，区别于每会话独立的 VirtualCart）；落盘根目录 `shopping_list.json`；待处理条目同文去重；冒烟 TDD（先红后绿：增/删/标记/清空/持久化/去重/空态）。
- **API** `web_server.py`：`/api/shopping_list` GET（items/pending_count/list_text）+ POST 五动作（add/remove/toggle_done/clear_done/clear，未知动作 ok:false）；`/api/health` 增 `list_pending`。
- **对话指令** `shopping_agent.py`：`记到清单：xxx` / `我的清单` / `从清单移除第N项` / `完成（取消完成）第N项`——插在购物车指令块**之前**（顺序敏感：购物车「移除第N项」正则会误吞「从清单移除第N项」）；纯规则，零 LLM 调用。
- **前端** `index.html`：侧边栏新 Tab「购物清单」（checklist 图标，置于虚拟购物车之前）+ 待处理数徽标（health 轮询与操作后双路刷新）+ 面板（输入框添加、待处理列表、已完成折叠区、清空已完成带确认、刷新）+ 条目三按钮（去推荐/完成/移除，内容 textContent 防注入）+ 对话页「我的清单」chip。配色全走主题变量。

**验证**（如实记录）：
- 模块冒烟：`python core/shopping_list.py` 通过；对话指令直调（临时 ChatSession，不入会话库）四条全过且 `shopping_list.json` 无残留。
- API 冒烟：重启服务验 8765 存活（health 含 list_pending）；GET 空态、add（中文）、toggle_done、clear_done、bogus→ok:false、clear 全过，数据清干净。**踩坑记录**：curl.exe 在 GBK 控制台发中文 JSON 会被编码打碎致「未知操作：」假象，换 Python urllib 纯 UTF-8 复测即正常——服务端无 bug，浏览器 fetch 场景不受影响。
- 浏览器走查（chrome-devtools）：侧边栏位置/图标正确；输入添加后徽标变 1；「去推荐」→ 自动切对话页、原文入框、焦点到位、**未发送**；「完成」→ 移入已完成折叠区、徽标归 0；折叠区展开显示删除线样式与「取消完成」按钮；「清空已完成」confirm 弹窗接受后清空；深色模式截图核对主题适配无破损；控制台无本次改动相关报错（仅既有 favicon 404）。**皮肤四套未逐一实测**（开发者指示跳过剩余验证；面板仅用主题变量，理论上随皮肤联动）。
