# 260913 开发日志

## 对话记忆 + 自由问答链路（问题疑惑区第2轮）

> 创建于 2026-09-13 00:27

**需求**：问题疑惑区「系统级prompt限制过硬」。定位过程：T2（条数动态化）实测已生效（该句解析出 top_n=5、per_platform_n=4，推荐输出 5 条）；开发者复测确认后指出真痛点是 **AI 只有单轮对话记忆、持续交互能力欠缺**。方向商讨后开发者选定方案 B（自由问答链路）+ 方案 1（末端兜底、LLM 自判可答）。spec/plan：`docs/project/全局/2026-09-12-对话记忆与自由问答-{design,plan}.md`。

**实施**（TDD：每任务先断言脚本红→实施→绿；8 任务完成 7 个代码任务）：
- **润色 prompt 动态化**（ai_client）：「TOP3/500字」写死改 `TOP{N}` + 字数上限按条数线性放宽（≤5 款 500 字起、每多 1 款 +100、封顶 1000），user_prompt 标签同步。
- **需求解析增强**（ai_client + request_parser）：`parse_shopping_request_with_llm` 新增 `history` 参数——user_prompt 注入「[最近对话]」块（≤8 条、单条截断 100 字）；sys_prompt 补指代/增量理解指令；schema 补 `top_n`/`per_platform_n` 字段。`RequestParser.parse` 透传 history；`_merge_llm_json` 合并条数**规则优先**（规则已解析到不覆盖，LLM 值 clamp 1..10）。
- **自由问答 LLM 能力**（ai_client）：新增第 4 个高层能力 `answer_free_question_with_llm(question, materials)`——只基于材料回答、材料没有如实说无法判断、绝不编造；要求新搜索/与材料无关时返回约定标记 `NEED_SEARCH`；失败返回 None。
- **对话滑动窗口**（shopping_agent）：`ChatSession._history`（≤8 条消息 = 4 轮）+ `HISTORY_MAX_MSGS` 常量；`chat()` 改包装（记录窗口，当前输入不重复计入），原逻辑改名 `_chat_impl`；`export_state/restore_state` 增 history 键（无损往返，旧存档无此键兼容）。
- **问答兜底接入路由**（shopping_agent）：`_chat_impl` 4.2/4.3 之间插 4.2.5——触发条件 = 疑问信号（短句 ≤40 字含 ？/为什么/哪个/哪个好 等）**或** 泛词模糊输入；`_try_free_qa` 组包材料（上次推荐摘要 + 历史窗口 100 字截断 + **档案白名单字段**，姓名/电话/地址绝不入 prompt）调 LLM；回答则展示，None/NEED_SEARCH 落回原澄清/搜索流程。parse 5 处调用点全部传 history。
- **材料摘要**（recommender）：`last_recommendation_brief()` 输出上次推荐紧凑列表（序号/名称/平台/店铺/到手价/总分/优缺点各 1 条/链接）。

**设计修正**（写计划时发现并修 spec）：「第2款和第4款哪个更耐穿？」会被规则提取出伪关键词「耐穿」直达搜索，原「泛词兜底处触发」到不了——故加疑问信号条件且插入点提前到搜索之前。

**验证**：7 个断言脚本（temp/test_t1_polish ~ test_t7_qa_flow）全过，覆盖——润色动态化 3/8 条两分支；历史注入/无 history 不出块/超长截断；条数合并规则优先+clamp+异常静默；解析原话回归 top_n=5；brief 摘要字段；窗口滑动 8 条上限/export-restore 往返/旧存档兼容/空输入不入窗；问答回退矩阵（LLM 屏蔽→澄清、可用→回答、NEED_SEARCH→原流程、无材料→不调用）、需求类输入不触发（省时延）、**隐私剔除断言**、伪关键词疑问句不误搜。测试卫生：全部脚本预先对 `searcher.search_real` 打桩（首版曾因「哪个好？」被提取为关键词误入真实搜索一次，已重写修正）；档案用内存替身，不写共享 profile.json。

**计划外偏差记录**：① T6 restore 原定 500 字截断导致 export/restore 往返不等（「查看档案」回复达 1204 字），改为无损恢复（prompt 侧已有 100 字截断）；② T7 场景F改用内存假档案（原计划直接 update_batch 会污染含开发者真实数据的 profile.json）；③ Edit 工具对含三引号的长 old_string 多次未命中，ai_client 润色段改用 python 脚本按精确文本替换。

**真机冒烟清单（待开发者执行，需已配置 API Key 的环境）**：
1. 「买一条夏天连衣裙 预算200」出推荐 → 「第2款和第4款哪个更耐穿？」→ 应回基于推荐材料的对比回答（非澄清、非搜索）；
2. 「再要2个」→ 按增量意图解析条数；
3. 「帮我搜下百元内的蓝牙耳机」→ 正常走搜索（不被问答误拦）；
4. 「随便来点便宜的」→ 回落品类澄清；
5. 重启服务后追问「刚才推荐里哪个最便宜？」→ 会话恢复后仍能基于此前推荐作答（history 落盘生效）。
