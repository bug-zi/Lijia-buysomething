## 1. 开场介绍（建议 1–2 分钟）

**一句话定位**：运行在自己电脑上的对话式购物 AI 助手——用一句自然语言说出购物需求，系统自动完成「建档 → 需求解析 → 跨平台限量搜索 → 五维评分 → TOP-N 推荐 → 下单模拟 → 物流跟踪 → 售后」全流程辅助。

**三个开场要点**：

1. **它解决什么**：跨平台购物信息分散、评价真假难辨、比价费时——用户只说需求，剩下的交给 Agent。
2. **它怎么建**：Python 纯标准库后端 + 单文件网页前端，双击即跑、零第三方依赖启动；大模型（智谱/DeepSeek/通义/硅基流动/豆包/Kimi，OpenAI 兼容协议）只做增强、不做决策，任何 AI 调用失败自动回退规则引擎。
3. **它的底线**（先立住，答辩常问）：绝不代用户支付；绝不编造商品数据——每条商品带「真实数据 / 演示数据」来源标注；抓取克制（每平台每次只看搜索结果页前 10 条，不翻页、不轮询）；遇验证码交还人工、绝不绕过。

## 2. 演示脚本（核心：跟着一次真实使用走）

> 建议总时长 8–12 分钟。每个场景给出「输入什么 → 屏幕上会发生什么 → 顺口讲什么」。
> 现场优先走**真实搜索**链路（已预热缓存）；若遇风控/验证码，按第 7 节预案顺势讲解或切演示模式。

### 场景 1 · 首次使用：手把手引导带练 + 建立个人档案（约 2.5 分钟，2026-09-16 二次升级：沉浸式任务模式）

- **做**：注册新账户进入 → 弹窗向导开场（第 1 节「认识助手」：欢迎与安全边界 → 设置账户，昵称**已按注册账户名预填**、选性别即时预览默认头像）。
- **讲**：从第 2 节起引导**收起弹窗、交给真实界面**——要点的东西被**白色虚线聚光圈**圈住、其余界面蒙上轻遮罩，旁边浮一张引导小卡（渐变头 + 全局进度 N/10 + 操作说明 + 跳过/下一步）——「不是看幻灯片，是手把手带着做」。
- **做**（第 2 节 用户中心）：亲点聚光的「用户中心」→ 聚光自动移到偏好卡 → 现场点一个主题色圆点 → 浮卡即时确认「做得好，已经生效」——**这里留白让嘉宾/观众随便玩**：换字体、字号、人群交互风格都行，体验好了自己点「下一步」；档案步点「分批引导录入」照常演示分批提问。
- **讲**（顺口）：偏好卡 = 字号字体/人群交互风格（AI 语气跟着变）；档案 = 所有推荐的永久参考，越全越准、追问越少。
- **做**（第 3 节 配置库）：亲点聚光的「配置库」→ Key 粘贴小步可现场演示也可「下一步」跳过（没 Key 也完全可用）→ 登录态卡现场扫码（窗口内自行扫码，程序绝不过手账号密码）。
- **做**（第 4 节 对话购物，全片第一处高潮）：亲点聚光的「对话购物」→ **示例需求已代填**，点发送 → 浮卡切「看 AI 干活」等待态（真实抓取 15-30 秒）→ **推荐一到达自动进入下一步** → 点浮卡「帮我填『买第1款』」再点发送 → 讲下单确认与支付风险提醒（可现场回复「确认」完成下单模拟，绝不代付）。
- **做**（第 4 节 收尾）：购物清单小步——需求已代填，点「添加」即完成；购物车小步讲收藏与降价监控；「完成准备」弹窗收尾。
- **答辩点**：引导分两类小步——**实践型**（偏好/档案/Key/登录态/清单）确认生效后**留白让用户自由体验**，玩够自己点「下一步」；**推进型**（进页/发需求/等推荐/买第X款）侦测到操作自动前进。遮罩只做视觉聚焦、从不拦截点击——**沉浸式但绝不绑架用户**；引导按账户只弹一次、随时可跳过本节/全部。
- **做**：完成或跳过引导后 → 输入「录入档案」→ 分批引导式提问（必填在前，每批可「跳过」、断点续录「继续建档」）；向导进行中输「查看档案」→ 档案照常展示（按【必填】【选填】分节）且**附「仍停在第 N/24 步」提示**，直接回答无缝续录。
- **讲**：档案 37 个字段，分**必填 10 项**（身高体重尺码、色系好恶、预算上限、优先因素、收货三要素——决定推荐准确度与下单）和 5 组选填（画像体型/风格场景/材质气候/品牌渠道/决策服务），存在本地，是后面推荐打分的依据；用户中心表单也按必填/选填分组，顶栏徽标按必填缺口亮「必填缺N项/已完善」。快捷命令演示：「查看档案」「修改身高=175」。

### 场景 2 · 主流程：说需求 → 推荐 → 下单模拟 → 物流（约 4 分钟，全片高潮）

- **输入**：「买一双跑鞋，日常运动穿，透气轻便的，预算300以内」
- **发生**（逐条指屏幕讲）：
  1. 需求被解析成结构化参数（品类/预算/用途/要求属性），规则引擎 + LLM 增强，档案里的预算上限作默认值——关键信息齐了，**不再反问、直接干活**；
  2. **需求直达搜索**：自动打开各平台搜索结果页限量抓取（每平台 ≤10 条卡片，默认 6）——强调「用户只需说需求，不用自己逛」；
  3. 预算初筛 → **五维评分**排序（详见第 3 节）；
  4. 输出 **TOP-N 推荐**（默认 3 条，也可指定要几条）：每款带优点、缺点、价格分析、适配说明、风险提示、评分表 + 横向对比。
- **指给老师看**：每条商品卡片上的数据来源标注（[真实数据] / [演示数据]）——「系统绝不编造数据，演示数据必须加声明」。
- **输入**：「买第2款」
- **发生**：订单草稿预览 + **支付风险提醒** → 明确回复「确认」后模拟下单（生成订单号+运单号）——强调「只模拟流程，绝不代付」。
- **发生**：物流按虚拟时间自动推进（已下单 → 已发货 → 运输中 → 派送中 → 已签收；新订单 10 分钟内加速走完 24 小时演示节奏）；「我的订单」Tab 看状态机与轨迹。
- **可补**：演示「售后」「取消」命令，讲状态机分支（已发货后只能售后、不能取消）。

### 场景 3 · 对话式增量调整与追问（约 2 分钟，最能体现 Agent 能力）

- **输入**：「想买个杯子」
- **发生**：**模糊需求先澄清**（2026-09-14 新增，同晚表单化）——AI 不瞎搜，弹出**分题表单**（4~6 问）：预算、场景、材质/容量等关键问题带选项**点选只勾选不提交**（可多选/改选），次要问题（颜色/功能款式）标「选填」给方向，每题可「其他」自填，末尾**补充栏**写 AI 没问到的；按「提交并搜索」合成一句话开搜。**讲**：「像真人导购先问清楚再推荐，一次问全、绝不连环盘问；不想填点『直接搜』」。
- **输入**（2026-09-14 新增）：「我想买一箱泡面」——或任意冷门品类如「想买个靠枕」「想买把机械键盘」
- **发生**：弹出的**不是通用卡，而是该商品专属问卷**——问卷由 AI 按关键词现场生成（泡面问口味/包装+囤货夜宵用途、靠枕问摆放场景/填充材质、键盘问轴体/连接方式），AI 超时或关 Key 自动落本地规则兜底——讲「问题跟着品类走，任何商品都能问出它独有的选购要点；AI 只是增强，挂了照样能问」。追问出表约 15~25 秒（打字动画期间），属正常。
- **输入**：「第二款不要黑色的，换白色的，预算升到400」
- **发生**：在原需求上**增量合并**（不要黑 vs 要白：排除优先——黑色被踢掉、白色成硬性要求），重新出推荐。
- **输入**：「第2款和第4款哪个更耐穿？」
- **发生**：**自由问答链路**——基于上次推荐材料和对话记忆回答对比，材料里没有的如实说；需要新搜索时自动落回搜索流程。
- **输入**：「再要2个」
- **发生**：解析出条数意图，输出 5 条（条数可指定 1–10）。
- **讲**：对话滑动窗口（最近 4 轮）注入解析与问答，跨轮次指代能懂；会话落盘本地 JSON，**重启服务后追问「刚才推荐里哪个最便宜」依然接得上**。

### 场景 4 · 界面与体验亮点快闪（约 2 分钟）

- **多会话**：顶栏会话列表钮，多窗口新建/切换/删除，会话可导出/分享 Markdown。
- **主题皮肤**：4 套皮肤 × 深浅模式即时切换，背景装饰（樱花/叶枝/落日/气泡）随皮肤联动，左上角 logo、标签页图标与 AI 头像也随皮肤换对应色系（现场切一个皮肤指 logo 讲）。
- **长输出折叠 + 快速跳转**：TOP3 推荐这类多商品长消息自动折叠成三行摘要卡（标题栏带价格/总分/数据源），消息顶部有「第X名 ¥价格 · 总分」跳转条，点击直达对应商品展开高亮——「AI 话多但界面不乱，只看想看的」（现场展开一款对比讲）。侧栏底部「使用贴士」自动轮播也可顺带一提。
- **用户中心**：点击头像即传自定义头像（长期存本机，对话里即时生效）、按性别挑默认头像、昵称、字号字体，以及「交互风格（人群）」——选学生党/上班族/长辈，AI 导购点评的语气会跟着变（现场切一个对比念两句）。
- **虚拟购物车**：收藏候选 + 降价监控开关。
- **图片多模态（加分项，网络允许时）**：传一张穿搭图「找同款」→ 视觉模型提取品类/颜色/风格出关键词；或多图对比出 Markdown 对比表。**必带一句**：「图片分析仅为视觉推测，以商品网页为准」。

### 场景 5 · 购物清单：需求池 → 对话 → 收藏闭环（约 1.5 分钟，2026-09-14 新增）

- **做**：侧边栏「购物清单」Tab（在虚拟购物车之前）→ 输入「夏天房间太热想凉快点」回车。
- **讲**：清单收藏的是**需求**不是商品——「突然想到但不知道该买啥、也懒得现在逛，先记下来，这就是购买前需求池」；侧边栏徽标显示待处理数。
- **做**：点该条「去推荐」→ 自动切到对话页、原文已填入输入框（**不会自动发送**）→ 现场补一句「预算300」再回车 → 走场景 2 的推荐链路 → 满意后「把第1款加入购物车」→ 回清单页点「完成」。
- **讲**：一条「清单（需求）→ 对话（推荐）→ 购物车（商品收藏）」的完整闭环；清单页对话里也能用：「记到清单：无线鼠标」「我的清单」「完成第1项」。
- **兜底**：整条链路纯本地规则（零 LLM、零抓取）——「去推荐」之后的推荐环节才联网，前面任何环节断网都能演。

### 场景 6 · 多账户：注册即用、数据互相隔离（约 1.5 分钟，2026-09-15 新增）

- **做**：退出登录（顶栏账户胶囊 → 退出）→ 登录门切「注册」→ 现场填用户名+邮箱+密码（如「小明 / xm@test.com / 1234」）→ 回车即进入主界面。
- **讲**：「注册填完三项就成功，不用邮箱验证——本地单机定位；密码加盐哈希存储，文件里看不到明文」。
- **做**：在这个新账户里看购物清单/购物车/订单（应为空）→ 点开顶栏账户胶囊 → **「切换账户」**（2026-09-16 新增，位于退出登录上方）→ 登录门副标题变为「切换账户：请登录其他账户…」→ 登回原账户（数据都在）——「不用退出再登录两步，一键直达换号」。
- **讲**：「每个账户独立的档案、订单、购物车、清单、会话，连 LLM API Key 都是按账户各存各的；电商平台登录态是机器级的，保持共享」。重启服务后不用重新登录（token 持久化）。
- **做**：留意新账户进入时自动弹出分节新手引导（2026-09-16 修复+升级）——「连『已看过引导』都是按账户各记各的，新账户走自己的首次流程；引导昵称还会预填注册用户名」。
- **做（2026-09-16 新增）**：指着顶栏账户胶囊——「用户名在左、头像在右；头像三级取值：上传的自定义 → 按性别默认头像 → 首字母色块」（可在用户中心现场换性别/传头像，顶栏即时变）。
- **做（2026-09-16 新增）**：点开胶囊 → 「注销账号」（暗红）→ 现场输错密码（弹窗带出错字就地重输）→ 输对密码 → 回登录门；再注册同名账户：全新空数据——「注销要密码确认、账户和数据目录一起真删，删完同名重开也是干净隔离的」。
- **讲（跨电脑）**：「所有账户数据只存本机、不进代码仓库——把代码传 GitHub 或换一台电脑，都是全新空白，互不可见；每台电脑各自注册自己的账户」。
- **兜底**：注册/登录/切换全程零 LLM 零抓取，断网可演；若现场注册的演示账户太多，用「注销账号」现场清掉即可（课后手动删则删 `accounts/<用户名>/` 目录与 `accounts.json` 对应条目；首次注册前的旧数据在首个注册账户里，勿删该账户）。

### 场景 7 · 消息站 + 回收站：操作有回执、删除可反悔（约 1.5 分钟，2026-09-16 新增）

- **做**：场景 2 下单/取消之后，点侧边栏「消息站」（未读徽标亮着）→ 展示「下单成功（支付模拟）」「订单已取消」两条回执卡片（订单号/原因/金额/未扣款声明都在）。
- **讲**：「操作类信息不挤占聊天流——对话购物只用来聊买东西，系统操作回执统一进消息站；类似微信的『服务通知』」。对话里取消订单也只回一句「完整回执已存入消息站」。
- **做**：切「对话购物」展开会话列表 → 删除一个会话（确认弹窗写明「移入回收站，3 天内可还原」）→ 点侧边栏「回收站」→ 条目在列（类型/摘要/删除时间/**剩约 X 天自动彻底删除**倒计时）→ 点「还原」→ 回会话列表，会话回来了。
- **讲**：「删除不立即真删，先进回收站、超 3 天未处理才自动彻底删除（自动清理也会记进消息站）——防手滑，可反悔」。覆盖：会话/购物车/清单/档案/API Key 配置；**如实说明两类例外**：清除网站登录态（凭据无法可靠快照还原）、注销账号（账户整体删除）。
- **兜底**：全链路纯本地规则零抓取，断网可演；课前先备好一条订单（走一遍场景 2 即可），消息站天然有内容。

## 3. 技术亮点讲解（答辩加分，建议 2–3 分钟）

1. **五维评分模型**（可解释，不是黑盒）：档案匹配度 30% + 性价比 25% + 真实口碑 20% + 差评风险 15% + 发货时效 10%，加权 0–100 分；TOP-N 内同平台尽量拉开，避免清一色。
2. **AI 增强 + 全链路兜底**：LLM 只做需求解析（结构化 JSON + 规则校验合并，规则优先）、评价摘要、导购点评润色、自由问答——**不做事实决策**；任何 AI 调用失败（超时/无 Key/异常）静默回退规则引擎，功能永不因 AI 失效而中断。现场可现场拔 Key 演示「AI 挂了系统照常工作」。
3. **真实数据三层回退**：真实搜索缓存（30 分钟 TTL）→ 真浏览器限量搜索（Patchright 驱动级反检测 + 本机系统浏览器 + 拟人化随机延迟）→ 演示 Mock 库（明确标注）。
4. **零依赖工程**：后端纯 Python 标准库 `http.server`，前端单文件 `index.html`，本地 JSON 文件当数据库，双击 `.bat` 就能跑——「拿到任何一台电脑都能现场复现」。
5. **虚拟时间物流**：订单状态机 + 时间加速推进（新单 10 分钟走完 24 小时），让全流程在演示时间内可完整走通。

## 4. 安全与诚实红线（必讲，也是差异化卖点）

- **不代支付**：只到「下单模拟（订单号）」为止，确认前后双风险提醒。
- **数据真实性**：每条商品带 `data_source` 标注；抓取失败如实告知；演示数据强制声明；**评价区如实展示**——真实抓取拿不到评价明细就明说「未抓取到」，绝不拿「综合评价良好」这类凑数话术充数。
- **Key 安全**：API Key 本地脱敏存储展示（只露前后 4 位），绝不回传前端明文。
- **抓取克制**：每平台每次 ≤10 条卡片、不翻页、不遍历、不轮询；真实有头浏览器；验证码/登录墙暂停并交还人工（自行扫码），程序绝不过手账号密码，不绕过平台风控。
- **隐私本地化**：档案、订单、会话全部只存本机 JSON，服务只绑 127.0.0.1，不上传任何服务器。
- **已知限制如实告知**（主动讲反而加分）：历史价格曲线暂不支持（仅当前价对比）；图片分析仅为视觉推测；真实抓取成功率受平台风控波动影响。

## 6. 答辩 Q&A 预案

| 可能的提问 | 建议回答要点 |
|---|---|
| 商品数据是真的吗？ | 三层回退保证：真实搜索缓存 → 真浏览器限量抓取 → 演示数据；每条带来源标注，演示数据强制声明，绝不编造 |
| 爬电商网站会不会有合规/封号风险？ | 克制策略：只看搜索结果页前 10 条、不翻页不轮询；真实浏览器拟人化访问；遇验证码交还人工、绝不绕过；定位是个人辅助工具 |
| 大模型在里面到底干什么？会不会胡说？ | 只做解析/摘要/润色/问答，不做事实决策；结构化 JSON 输出 + 规则校验合并；失败自动回退规则引擎，所以 AI 坏了功能还在 |
| 为什么不用数据库？ | 单机个人工具，数据量小；JSON 文件即数据库、零部署零依赖，与「双击即跑」定位一致 |
| 它会替我付钱吗？ | 红线设计：只模拟下单流程，绝不代支付，前后双风险提醒 |
| 为什么我随口说个东西，它还要反问我？ | 模糊需求缺关键维度（预算/用途/品类属性）时先澄清再搜，推荐更准；一轮问完、可回「直接搜」跳过，绝不无限盘问 |
| 推荐里的评价是真的吗？ | 评价区只展示真实抓到的评价明细；抓不到就如实标注「未抓取到」，不编造不凑数 |
| 和淘宝问问、慢慢买比价有什么区别？ | 电商 AI 导购限单平台；比价工具没有个性化档案和对话交互；通用大模型拿不到实时真实数据还容易编——本项跨平台统一打分 + 个人档案驱动 + 全流程闭环 + 来源诚实标注 |
| 推荐分数怎么算的？可信吗？ | 五维加权（30/25/20/15/10），逐项可解释；每条推荐附评分表和适配说明，用户可自己核对 |
| 现场断网 / 没 Key 怎么办？ | 全链路规则兜底 + 演示数据模式照常出完整流程；另有 CLI 全流程回归（`python shopping_agent.py demo`，18 个用例） |
| 物流信息是真的吗？ | 如实告知：虚拟时间模拟推进，用于演示全流程闭环，不接真实快递 API（真实单号查询在候选池） |
| 购物清单和购物车有什么区别？ | 清单存**推荐前的需求**（可以只是一句模糊痛点，如「夏天房间太热」），购物车存**推荐后的具体商品**（有价格有链接可监控降价）；链路是 清单 → 对话 → 购物车 → 订单，各管一段互不重复 |
| 把代码传 GitHub、同伴 clone 后能看到我账户的数据吗？ | 不能。账户数据和账户表都在 .gitignore 里，不随仓库走——每台电脑是独立环境，各自注册各自隔离；即使注册同名账户也是空白账户，电商登录态更是只存在本机浏览器配置里 |
| 后续还打算做什么？ | 候选池：推荐权重按需求动态调整、真实快递单号查询 API、图片多模态增强——先自用攒真实痛点再立项 |
