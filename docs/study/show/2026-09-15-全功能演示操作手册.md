# 全功能演示操作手册（逐步操作 + 可直接复制的提示词）

> 创建于 2026-09-15，适用版本：dev 分支（含 67ad0c6 及此前全部功能）。
> 定位：课堂全功能演示的**照做型手册**——每一步点什么、输什么提示词、屏幕会出现什么。
> 演示话术展开版、答辩 Q&A、分工建议见 `docs/project/演示汇报.md`（正本）；本文档是其操作层浓缩，口令均已对照代码核实。

---

## 第 0 步 · 课前准备（开课前 30 分钟）

1. **启动服务**：双击 `启动购物助手-网页版.bat`，浏览器打开 `127.0.0.1:8765`，确认页面能打开。
2. **配 Key**：「AI 设置」Tab → 填入智谱 Key（glm-4-flash 免费档）→ 保存，确认显示脱敏 Key（前后 4 位）。
3. **登录态**：课前对京东、淘宝各扫码登录一次（引导第 3 步的登录态卡片入口），之后免重复登录。
4. **缓存预热（关键）**：提前 30 分钟内，在对话框输入下面这条跑一遍，让真实搜索缓存生效：

   ```
   买一双跑鞋，日常运动穿，透气轻便的，预算300以内
   ```
5. **重置新手引导**（用于场景 1 重演）：按 F12 打开控制台，输入 `localStorage.removeItem("sa_onboarded")` 回车，刷新页面 → 引导会重新弹出。
6. **界面**：浏览器窗口放大（Ctrl + 加号放大字体）；用户中心预选一套皮肤；**提前录一段完整流程录屏备用**。

## 场景 1 · 新手引导 + 建档（约 2 分钟）


| 操作 | 输入/点击                                            | 屏幕反应                                                                  |
| ------ | ------------------------------------------------------ | --------------------------------------------------------------------------- |
| 1    | 刷新页面                                             | 4 步引导自动弹出：欢迎 → 昵称+性别+头像 → 购物网站账户（可跳过）→ 就绪 |
| 2    | 引导第 2 步选性别                                    | 立刻预览对应默认头像（讲：对话里你和 AI 各有专属形象）                    |
| 3    | 输入                                                 | `录入档案`                                                                |
| 4    | 按提示回答 2–3 批（如身高体重、色系偏好），然后输入 | `跳过`                                                                    |
| 5    | 输入                                                 | `查看档案`                                                                |
| 6    | 向导进行中再输入                                     | `修改身高=175`                                                            |

- 顺序讲点：第 5 步档案页会附「仍停在第 N/19 步」提示 → **「向导不是死流程，中途查档案、提新需求都行，进度不丢」**。

## 场景 2 · 主流程：说需求 → 推荐 → 下单 → 物流（约 4 分钟，高潮）

1. 输入（课前预热过的原话，缓存直接命中）：

   ```
   买一双跑鞋，日常运动穿，透气轻便的，预算300以内
   ```

   出结果时逐条指屏幕讲：需求被解析成结构化参数 → 自动跨平台限量搜索（每平台 ≤10 条）→ 五维评分 → TOP3 推荐；**指商品卡片上的 [真实数据]/[演示数据] 标注**。
2. 输入：

   ```
   买第2款
   ```

   → 订单草稿 + 支付风险提醒。
3. 输入：

   ```
   确认
   ```

   → 生成订单号 + 运单号（讲：只模拟流程，绝不代付）。
4. 切「我的订单」Tab：看状态机与轨迹（新单 10 分钟内走完 24 小时演示节奏，可稍后再回来看状态推进）。
5. 可选补刀：输入 `取消`（或 `售后`）讲状态机分支——已发货后只能售后、不能取消。

## 场景 3 · 对话式调整与追问（约 3 分钟）

> **顺序已按安全性调整**：先做「增量调整/追问」（此时上次推荐还是连衣裙，指代不乱），**再**做「杯子/泡面」这两个会开新搜索的演示。演示汇报.md 原稿把杯子放在增量之前，现场照原顺序打，「第二款太宽松」会指到杯子上，务必按下面顺序。

**3a. 接连衣裙上下文：**

1. 输入：

   ```
   第二款不要黑色的，换白色的，预算升到400
   ```

   → 增量合并重新推荐（讲：排除项优先——黑色被踢掉、白色成硬性要求，预算同步上调）。
2. 输入：

   ```
   第2款和第4款哪个更耐穿？
   ```

   → 自由问答链路，基于对话记忆回答。
3. 输入：

   ```
   再要2个
   ```

   → 输出 5 条（条数可指定 1–10）。
4. 讲点：**重启服务后**追问「刚才推荐里哪个最便宜」依然接得上——会话落盘本地 JSON。

**3b. 新需求（开新搜索）：**

5. 输入：

   ```
   想买个杯子
   ```

   → 弹出**分题澄清表单**（4~6 问）：现场点选几个选项（只勾选不提交，可多选改选）→ 某题选「其他」自填 → 末尾补充栏写一句 → 点「提交并搜索」。讲：「像真人导购先问清楚；不想填可点『直接搜』」。
6. 输入：

   ```
   我想买一箱泡面
   ```

   → 弹出的**不是通用表单，而是泡面专属问卷**（口味/包装/囤货用途——AI 现场生成，等 15~25 秒属正常，打字动画期间正好讲台词）。讲：「问题跟着品类走；AI 挂了自动落本地规则兜底，照样能问」。

## 场景 5 · 购物清单闭环（约 1.5 分钟）

1. 侧边栏点「购物清单」Tab → 输入框打：

   ```
   夏天房间太热想凉快点
   ```

   回车 → 讲：「收藏的是需求不是商品，购买前需求池」；侧栏徽标显示待处理数。
2. 点该条「去推荐」→ 自动切到对话页、原文已填入输入框（**不会自动发送**）→ 手动补成：

   ```
   夏天房间太热想凉快点，预算300
   ```

   回车 → 走推荐链路。
3. 输入 `把第1款加入购物车` → 回清单页点该条「完成」。
4. 讲完整闭环：「清单（需求）→ 对话（推荐）→ 购物车（商品）→ 订单」；再回对话页演示口令：`记到清单：无线鼠标` → `我的清单` → `完成第1项`。

## 收尾 · 「AI 挂了系统照常」兜底演示（约 1 分钟，答辩杀手锏）

1. 「AI 设置」Tab → 清掉 Key。
2. 回对话页输入：

   ```
   买个蓝牙耳机，预算200
   ```
3. → 推荐照样出、只是没有 AI 润色点评。讲：「LLM 只做增强不做决策，任何 AI 失败静默回退规则引擎，功能永不中断」。
4. **记得把 Key 填回去**（若后面还有问答环节要用 AI）。

最后口头过一遍红线四条（不代付 / 数据带来源标注 / 抓取克制 ≤10 条 / 隐私全本地只绑 127.0.0.1），收尾。

## 应急口令速查（现场出意外时照打）


| 情况                | 输入                                                 |
| --------------------- | ------------------------------------------------------ |
| 弹出登录/验证码窗口 | 手动扫码后回对话页输`继续抓取`                       |
| 澄清表单不想填      | 点「直接搜」                                         |
| 建档中途要退出      | 输`跳过`；之后输 `继续建档` 断点续录                 |
| 搜索太慢            | 顺势讲三层回退；或换预热过的需求；彻底不行播备用录屏 |
| 服务挂了            | 重启`.bat`；查 `%TEMP%\shopping_agent_web_error.log` |

## 与演示汇报.md 的差异说明

本文档对场景 3 的内部顺序做了安全性调整（增量调整提前到「杯子/泡面」新搜索之前），理由：澄清表单与专属问卷会开新搜索、覆盖「上次推荐」上下文，若先演杯子再输「第二款太宽松」，指代会落到杯子上。此差异已同步提请修订 `docs/project/演示汇报.md` 正本（待开发者确认）。
