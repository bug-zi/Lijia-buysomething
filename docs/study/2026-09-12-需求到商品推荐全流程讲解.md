# 从「买一个降噪耳机，1500以下，京东」到商品推荐：全流程讲解

> 创建于 2026-09-12
> 来源：开发者与 AI 的问答整理（study 学习笔记）
> 适用版本：2026-09-12 真实搜索功能落地后（Patchright 基座 + 京东新版搜索页适配）

## 旅程总览

一句话共经过 **7 站**：前端 → 意图分流 → 需求解析 → 浏览器真实搜索 → 卡片转商品 → 五维打分 → 格式化输出。全程约 10-30 秒，其中浏览器阶段（第 4 站）占大头。

---

## 第 1 站：前端 → HTTP（约 0.1 秒）

`index.html` 聊天框回车 → `POST /api/chat` 带上你的话。`web_server.py`（只监听 127.0.0.1）把消息交给全局唯一的 `ChatSession` 单例（`SESSION_LOCK` 加锁防并发）。

## 第 2 站：意图分流（shopping_agent.chat，毫秒级）

一句话要过 8 道关卡，像安检，按优先级依次排查：

1. 档案录入模式中？（建档未完成时所有输入都进档案收集）
2. 档案命令（录入档案/查看档案/修改身高=175…）
3. 订单 / 物流 / 售后命令
4. 购物车 / 取消 / 「继续抓取」等流程命令
5. 是否粘贴了商品链接（有 → 走链接细抓对比流程）
6. 「演示模式」指令
7. 待确认订单的「确认」
8. 都不是 → 进入**需求解析**

「买一个降噪耳机，1500以下，京东」在所有关卡都不命中，落到需求解析。

## 第 3 站：需求解析（request_parser，0.1 秒或 +2-5 秒）

规则引擎正则先跑，本句解析结果：

| 字段 | 值 | 来源 |
|---|---|---|
| keyword | 降噪耳机 | 「降噪耳机」 |
| price_max | 1500 | 「1500以下」 |
| platforms | ["京东"] | 「京东」 |

若配置了 LLM Key，解析结果会以 JSON 形式交给大模型再增强一遍（补全品类归一、纠错等）；LLM 失败**静默回退**规则结果，绝不阻断流程。产出结构化 `ShoppingRequest` 对象。

## 第 4 站：浏览器真实搜索（web_scraper.search_platform，8-20 秒，全流程心脏）

1. **启动**：Patchright 驱动 → 真实 Chrome（channel 优先）+ `.browser_profile` 持久化会话（登录过则直接复用，短期免扫码）。注意：**Patchright 生效时不注入任何自定义 stealth 脚本**——叠加注入反而暴露自动化特征（2026-09-12 实测教训，曾导致京东扫码登录一直失败）；
2. **导航**：打开 `search.jd.com/Search?keyword=降噪耳机`，两段式 goto（domcontentloaded 30s → commit 45s 重试）；
3. **墙检测**（`_detect_search_wall`，搜索页专用，避免把导航栏「请登录」、轮播「slider」误判为墙）：
   - 登录墙 → **同一个窗口**跳登录页原地等扫码（≤3 分钟）→ 成功后自动重搜；
   - 验证码/滑块 → 交还人工，回复「继续抓取」续跑；
4. **慢速滚动** 3 步促发懒加载；
5. **提取前 6 张卡片**（克制上限 ≤10）：京东新版搜索页卡片为 `plugin_goodsCardWrapper`，带 `data-sku` 属性、无 `<a>` 链接——
   - 标题：`[class*='goods_title_container']`
   - 价格：价格容器文本，被拆成多个 span 时用卡片文本 `¥\d+` 兜底正则
   - 销量：`[class*='goods_volume']`（"已售2万+" → 20000）
   - 图片：360buyimg CDN
   - 链接：`data-sku` 拼 `https://item.jd.com/{sku}.html`

## 第 5 站：卡片 → 商品对象（product_searcher，毫秒级）

每张卡片经 `_product_from_card` 转成跨平台统一的 `Product` 结构。原则：**解析失败的字段留 0/空，绝不编造**；`data_source="真实"` 如实标注。

## 第 6 站：五维打分（recommender，毫秒级）

6 条商品各自打分排序取 TOP3。权重：

| 维度 | 权重 | 说明 |
|---|---|---|
| 档案匹配度 | 30% | 对照 `user_profile.json` 个人档案 |
| 性价比 | 25% | 含预算 1500 贴合度、销量 |
| 真实口碑 | 20% | **搜索卡片层无评价数据，此项贡献为 0** |
| 差评风险 | 15% | 同上，卡片层无差评数据 |
| 发货时效 | 10% | 卡片层无此数据 |

> 这就是「深挖某款请发详情链接」提示存在的原因：链接细抓会打开详情页提取评价/规格，打分更准。

## 第 7 站：格式化输出 + 回程（recommender.format_top3）

生成 Markdown：每款含名称、📦 真实标注、店铺、优缺点（≥3 条，规则生成）、评分表、🔗 商品链接；若配置了 LLM Key 还会并行调 LLM 生成导购点评（7 秒总预算，超时静默兜底）。末尾附筛选条件与"深挖发链接"提示 → JSON 回前端 → Markdown 渲染到聊天流。

---

## 异常分支（同一条路的岔路）

| 情况 | 行为 |
|---|---|
| 结果 <3 条或全失败 | 如实告知原因 + 回退老路径（提示粘贴 1-5 个链接细抓对比） |
| 验证码 / 滑块 | 交还人工，回复「继续抓取」续跑 |
| 加载超时（疑似风控） | 两段式重试 → 失败截图存 `temp/` → 交还人工 |
| 未配置驱动（patchright/playwright） | 提示「安装浏览器驱动」，当前以 ⚠️ 演示数据兜底 |

## 与链接细抓流程的关系

「输入需求」走的是**限量搜索**（每平台 ≤10 条卡片，快，但无评价数据）；「粘贴链接」走 `_flow_grab_and_compare` 详情页细抓（逐个打开详情页，提取价格/评价/规格，打分更准）。两者共用同一套五维打分与 TOP3 输出，互补而非替代。
